# Банковская система

Учебный проект на Python для практики объектно-ориентированного программирования.

Проект представляет банковскую систему, которая позволяет управлять клиентами и счетами, выполнять транзакции, обрабатывать очереди, контролировать риски и вести журнал аудита.

Данные хранятся в памяти приложения. Для журнала аудита дополнительно поддерживается сохранение в JSONL-файл.

## Возможности проекта

- создание клиентов банка;
- проверка возраста клиента;
- открытие банковских счетов;
- пополнение и снятие средств;
- накопительные счета;
- премиальные счета с овердрафтом;
- инвестиционные счета;
- заморозка, разморозка и закрытие счетов;
- аутентификация клиентов;
- блокировка после трёх неверных попыток;
- фиксация подозрительных действий;
- ограничение операций в ночное время;
- поиск банковских счетов;
- расчёт общих балансов;
- рейтинг клиентов;
- внутренние и внешние переводы;
- комиссии за внешние переводы;
- конвертация валют;
- очередь транзакций;
- приоритеты;
- отложенные операции;
- отмена транзакций;
- повторные попытки;
- журналирование ошибок;
- аудит банковских операций;
- сохранение аудита в память и файл;
- анализ риска транзакций;
- блокировка опасных операций;
- отчёты по безопасности.

## Банковские счета

### AbstractAccount

Абстрактный базовый класс банковского счёта.

Содержит:

- уникальный номер;
- данные владельца;
- защищённый баланс;
- валюту;
- статус.

Определяет обязательные методы:

- `deposit()`;
- `withdraw()`;
- `get_account_info()`;
- `__str__()`.

### BankAccount

Базовая реализация банковского счёта.

Поддерживает:

- пополнение;
- снятие;
- проверку суммы;
- проверку статуса;
- запрет отрицательного баланса;
- автоматическую генерацию короткого UUID.

### SavingsAccount

Накопительный счёт.

Дополнительные возможности:

- минимальный остаток;
- месячная процентная ставка;
- начисление процентов через `apply_monthly_interest()`.

После снятия баланс не может стать меньше установленного минимального остатка.

### PremiumAccount

Премиальный счёт.

Дополнительные возможности:

- увеличенный лимит снятия;
- овердрафт;
- фиксированная комиссия.

Баланс может становиться отрицательным только в пределах установленного овердрафта.

### InvestmentAccount

Инвестиционный счёт с виртуальным портфелем.

Поддерживаемые типы активов:

- `stocks`;
- `bonds`;
- `etf`.

Метод `invest()` распределяет часть свободного баланса между активами.

Метод `project_yearly_growth()` рассчитывает ожидаемый годовой прирост портфеля.

Реальные ценные бумаги, котировки и внешние API не используются.

## Иерархия счетов

```text
AbstractAccount
└── BankAccount
    ├── SavingsAccount
    ├── PremiumAccount
    └── InvestmentAccount
```

Все типы счетов используют общий интерфейс, но переопределяют правила снятия и представления данных.

## Клиенты

Класс `Client` хранит:

- ФИО;
- уникальный идентификатор;
- возраст;
- контакты;
- статус;
- список номеров счетов.

Регистрация разрешена только клиентам в возрасте от 18 лет.

### Статусы клиентов

- `active` — клиент активен;
- `blocked` — клиент заблокирован.

После трёх последовательных неверных попыток входа клиент получает статус `blocked`.

## Управление банком

Класс `Bank` управляет клиентами, счетами и защищённым выполнением транзакций.

Основные методы:

- `add_client()` — добавить клиента;
- `open_account()` — открыть счёт;
- `close_account()` — закрыть счёт;
- `freeze_account()` — заморозить счёт;
- `unfreeze_account()` — разморозить счёт;
- `authenticate_client()` — проверить пароль;
- `search_accounts()` — найти счета;
- `get_total_balance()` — получить балансы банка;
- `get_clients_ranking()` — построить рейтинг;
- `process_transaction()` — проверить риск и выполнить транзакцию.

## Статусы счетов

- `active` — счёт активен;
- `frozen` — счёт заморожен;
- `closed` — счёт закрыт.

Пополнение и снятие доступны только для активных счетов.

## Безопасность клиентов и счетов

Банк фиксирует:

- неудачные попытки входа;
- попытки управления счетами в запрещённое время.

Открытие, закрытие, заморозка и разморозка счетов запрещены с 00:00 до 05:00.

Ограничение относится к операциям управления счетами. Денежные транзакции проходят отдельный анализ риска.

Пароли применяются только в рамках учебной модели и хранятся в памяти приложения.

## Банковская аналитика

### Общий баланс

Метод `get_total_balance()` возвращает остатки на счетах по каждой валюте.

Стоимость инвестиционного портфеля не включается в свободный баланс инвестиционного счёта.

### Рейтинг клиентов

Метод `get_clients_ranking()` формирует рейтинг по общей сумме средств в выбранной валюте.

Суммы разных валют не складываются без конвертации.

## Транзакции

Класс `Transaction` представляет денежный перевод между двумя счетами.

Транзакция содержит:

- идентификатор;
- тип;
- сумму;
- валюту;
- комиссию;
- отправителя;
- получателя;
- статус;
- причину отказа или отмены;
- время создания;
- запланированное время;
- время завершения;
- количество попыток.

Если идентификатор не передан, создаётся короткий UUID.

### Типы транзакций

- `internal_transfer` — внутренний перевод;
- `external_transfer` — внешний перевод с комиссией.

### Статусы транзакций

- `pending` — ожидает;
- `processing` — обрабатывается;
- `completed` — выполнена;
- `failed` — завершена с ошибкой;
- `cancelled` — отменена.

## Очередь транзакций

Класс `TransactionQueue` поддерживает:

- добавление транзакций;
- проверку дублирования;
- приоритеты;
- порядок добавления;
- отложенные операции;
- отмену.

### Приоритеты

- `LOW`;
- `NORMAL`;
- `HIGH`.

Сначала выбирается доступная транзакция с наибольшим приоритетом.

При одинаковом приоритете первой выбирается транзакция, добавленная раньше.

Отложенная операция не выполняется раньше `scheduled_at`.

## Обработка транзакций

Класс `TransactionProcessor` отвечает за:

- проверку счетов;
- комиссии;
- конвертацию;
- списание;
- зачисление;
- повторные попытки;
- статусы;
- фиксацию ошибок;
- обработку очереди.

Перевод запрещается, если:

- счёт отправителя заморожен;
- счёт получателя заморожен;
- один из счетов закрыт;
- валюта транзакции не совпадает с валютой отправителя;
- отсутствует курс конвертации;
- недостаточно средств;
- обычный счёт имеет отрицательный баланс.

Для списания вызывается полиморфный метод `withdraw()` соответствующего типа счёта.

## Комиссии

Внутренний перевод не имеет комиссии.

Для внешнего перевода:

`commission = amount × external_commission_rate`

Со счёта отправителя списываются сумма и комиссия.

Получателю зачисляется исходная сумма перевода.

Если отправителем является `PremiumAccount`, отдельно применяется фиксированная комиссия премиального счёта.

## Конвертация валют

Курсы передаются в `TransactionProcessor`:

```python
conversion_rates = {
    (Currency.USD, Currency.RUB): Decimal("80"),
    (Currency.RUB, Currency.USD): Decimal("0.0125"),
}
```

Если валюты различаются:

`recipient_amount = amount × conversion_rate`

Результат округляется до двух знаков по правилу `ROUND_HALF_UP`.

Автоматическое получение реальных курсов не выполняется.

## Повторные попытки

`max_retries` определяет количество повторов после первой попытки.

Логические ошибки не повторяются:

- замороженный счёт;
- закрытый счёт;
- недостаточно средств;
- отсутствующий курс;
- некорректная операция.

Неожиданные технические ошибки повторяются до исчерпания разрешённого количества попыток.

## Журнал ошибок процессора

Ошибки обработки сохраняются в `TransactionProcessor.error_log`.

Запись содержит:

- идентификатор транзакции;
- номер попытки;
- текст ошибки;
- время ошибки.

## Аудит

Класс `AuditLog` фиксирует события банковской системы.

Запись аудита содержит:

- время;
- уровень;
- тип события;
- сообщение;
- ID клиента;
- ID транзакции;
- дополнительные данные.

### Уровни аудита

- `info`;
- `warning`;
- `error`;
- `critical`.

### События транзакций

- `transaction_requested`;
- `risk_assessment`;
- `transaction_completed`;
- `transaction_failed`;
- `transaction_blocked`.

## Хранение аудита

Записи сохраняются:

- в памяти приложения;
- в файле `logs/audit.jsonl`.

Используется формат JSON Lines: каждая строка является отдельным JSON-объектом.

При сохранении выполняются преобразования:

- `datetime` → строка ISO 8601;
- `Decimal` → строка;
- `Enum` → значение перечисления.

Новые записи добавляются в конец файла.

Папка `logs/` создаётся автоматически и исключается из Git.

## Фильтрация аудита

Метод `AuditLog.filter()` поддерживает фильтрацию по:

- уровню;
- типу события;
- клиенту;
- транзакции;
- начальному времени;
- конечному времени.

Фильтры можно комбинировать.

## Анализ рисков

Класс `RiskAnalyzer` проверяет транзакцию до изменения балансов.

Анализируются четыре признака:

- крупная сумма;
- частые операции;
- перевод новому получателю;
- ночная операция.

### Крупная сумма

Операция считается крупной, если сумма больше или равна `large_amount_threshold`.

Порог настраивается при создании анализатора.

### Частые операции

Операции считаются частыми, если количество запросов достигает установленного лимита внутри заданного интервала.

По умолчанию используется лимит три операции за пять минут.

### Новый получатель

Получатель считается новым, если клиент ранее не выполнял успешный перевод на его счёт.

Неуспешные и заблокированные операции не делают получателя известным.

### Ночная операция

Операция считается ночной в период:

`00:00 <= время < 05:00`

## Уровни риска

Каждый найденный признак добавляет один балл.

- 0 признаков — `low`;
- 1 признак — `medium`;
- 2 и более признаков — `high`.

Операции низкого и среднего риска разрешаются.

Операции высокого риска блокируются банком.

## Защищённая обработка

Для выполнения операции с контролем риска используется:

```python
bank.process_transaction(
    transaction,
    transaction_processor,
)
```

Последовательность:

1. Проверка транзакции и процессора.
2. Проверка регистрации счёта отправителя.
3. Определение клиента.
4. Запись запроса в аудит.
5. Анализ риска.
6. Запись оценки риска.
7. Блокировка высокого риска.
8. Передача разрешённой операции в процессор.
9. Запись результата.

При блокировке:

- балансы не изменяются;
- процессор не запускается;
- статус становится `failed`;
- записывается причина;
- количество попыток остаётся равным нулю;
- создаётся критическая запись аудита.

Прямой вызов `TransactionProcessor` является низкоуровневым способом обработки и не выполняет анализ риска.

## Отчёты аудита

Класс `AuditReport` формирует три отчёта.

### Подозрительные операции

`get_suspicious_operations()` возвращает операции среднего и высокого риска.

### Риск-профиль клиента

`get_client_risk_profile()` возвращает:

- количество оценённых операций;
- распределение по уровням риска;
- количество блокировок;
- максимальный риск.

### Статистика ошибок

`get_error_statistics()` возвращает:

- общее количество записей `error` и `critical`;
- количество ошибок по типам событий.

Оценка высокого риска и последующая блокировка являются отдельными критическими событиями.

## Валюты

Поддерживаются:

- `RUB`;
- `USD`;
- `EUR`;
- `KZT`;
- `CNY`.

Без переданного курса конвертация между валютами не выполняется.

## Исключения

В проекте используются собственные исключения:

- `AccountFrozenError`;
- `AccountClosedError`;
- `InvalidOperationError`;
- `InsufficientFundsError`.

## Установка

Клонировать репозиторий:

```bash
git clone <URL-репозитория>
```

```bash
cd <название-папки>
```

```powershell
.venv\Scripts\Activate.ps1
```

