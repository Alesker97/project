# Асинхронный веб-краулер

Учебный проект асинхронного веб-краулера на Python.

Проект создаётся поэтапно и демонстрирует применение:

- асинхронного программирования;
- конкурентного выполнения сетевых запросов;
- управления HTTP-соединениями;
- парсинга HTML;
- очередей с приоритетами;
- ограничения конкурентности;
- ограничения глубины обхода;
- фильтрации URL;
- обработки сетевых ошибок;
- структурированного логирования;
- тестирования асинхронного кода.

Краулер загружает страницы, извлекает структурированные данные, автоматически обходит найденные ссылки, соблюдает ограничения скорости и правила `robots.txt`, сохраняет результаты в файлы и SQLite.

Ограничение нагрузки и соблюдение правил сайтов:

- отдельные скоростные лимиты для доменов или один глобальный лимит;
- минимальные и случайные задержки между запросами;
- асинхронная загрузка и кэширование `robots.txt`;
- проверка запретов для настроенного User-Agent;
- соблюдение `Crawl-delay`, включая дробные секунды;
- проверка разрешений при перенаправлениях страниц;
- повторы временных ошибок с экспоненциальным backoff;
- статистика частоты запросов, задержек, повторов и блокировок.

Обработка ошибок включает классификацию, отдельный `RetryStrategy`, лимиты и задержки повторов по типам ошибок, увеличение таймаутов при повторах, историю попыток и JSON-отчёт. Локальная демонстрация запускается вместе с `python -m src.main` и сохраняет `output/error_report.json`.

Для самостоятельного применения стратегии передайте `raise_on_error=True`: это заставляет `fetch_url()` выполнить одну попытку и выбросить классифицированную ошибку. Без этого флага краулер сам применяет повторы и по прежнему возвращает пустую строку при неудаче.

```python
from src.crawler.errors import NetworkError, TransientError
from src.crawler.retry_strategy import RetryStrategy

strategy = RetryStrategy(
    max_retries=3,
    backoff_factor=2.0,
    retry_on=[TransientError, NetworkError],
)
result = await strategy.execute_with_retry(
    crawler.fetch_url, "https://example.com", raise_on_error=True,
)
```

Статистика доступна через `get_error_stats()`, полный отчёт — через `get_error_report()`. Параметры `connect_timeout`, `read_timeout` и `total_timeout` задают исходные таймауты; каждая повторная попытка увеличивает их в `1.5` раза. Для HTTP `429` пауза удваивается, для HTTP `500` действует предел в два повтора. Circuit breaker пока не включён.

Хранение данных обеспечивают `DataStorage`, `JSONStorage`, `CSVStorage` и `SQLiteStorage`. Краулер автоматически сохраняет успешно разобранные страницы; ошибки записи повторяются и отражаются в `get_storage_stats()` без остановки обхода. JSON Lines подходит для больших результатов, CSV поддерживает экранирование и кодировки, SQLite — индексы и пакетные вставки. Алгоритм описан в [документации по хранению](docs/algorythms/data_storage.md).

```python
from src.crawler.async_crawler import AsyncCrawler
from src.storage import SQLiteStorage

crawler = AsyncCrawler(storage=SQLiteStorage("output/pages.db", batch_size=50))
try:
    await crawler.crawl(["https://example.com"], max_pages=10)
    print(crawler.get_storage_stats())
finally:
    await crawler.close()
```

## Асинхронный HTTP-клиент

Класс `AsyncCrawler` находится в файле:

```text
src/crawler/async_crawler.py
```

Пример создания клиента:

```python
crawler = AsyncCrawler(
    max_concurrent=10,
    max_concurrent_per_domain=2,
    max_depth=2,

```

Основные методы:

- `fetch_url()` — загрузка одной страницы;
- `fetch_urls()` — параллельная загрузка списка URL;
- `fetch_and_parse()` — загрузка и парсинг одной страницы;
- `crawl()` — автоматический обход страниц;
- `get_crawl_stats()` — получение статистики обхода;

## HTTP-сессия и connection pooling

`AsyncCrawler` использует одну экземплярную `aiohttp.ClientSession`.

Сессия создаётся при первом HTTP-запросе и повторно используется при последующих запросах.

Это обеспечивает:

- повторное использование соединений;
- connection pooling;
- сокращение накладных расходов;
- централизованное управление таймаутами;
- корректное освобождение ресурсов.

После завершения работы с клиентом вызывается:

```python
await crawler.close()
```

## Управление конкурентностью

Класс `SemaphoreManager` находится в файле:

```text
src/concurrency/semaphore_manager.py
```

Он управляет двумя ограничениями:

- глобальным количеством одновременных запросов;
- количеством одновременных запросов к одному домену.

Например:

```python
crawler = AsyncCrawler(
    max_concurrent=10,
    max_concurrent_per_domain=2,
)
```

При такой конфигурации одновременно выполняется не более десяти запросов, при этом к одному домену отправляется не более двух запросов.

Менеджер также отслеживает текущее и максимальное количество активных задач.

## Rate limiting и robots.txt

Пример настройки скорости и правил обхода:

```python
crawler = AsyncCrawler(
    max_concurrent=5,
    requests_per_second=2.0,
    respect_robots=True,
    min_delay=0.5,
    jitter=0.1,
    user_agent="MyBot/1.0",
    max_retries=2,
    backoff_factor=0.5,
)
```

`RateLimiter` разделяет начала запросов интервалом:

```text
max(1 / requests_per_second, min_delay, Crawl-delay) + uniform(0, jitter)
```

По умолчанию лимит равен одному запросу в секунду для каждого домена. При `per_domain=False` применяется один общий лимит. Семафоры по-прежнему ограничивают количество одновременных запросов.

`RobotsParser` загружает правила асинхронно и кэширует их отдельно для каждой комбинации схемы, hostname и порта. Кэш действует всё время жизни экземпляра. Краулер использует одинаковый User-Agent в HTTP-заголовке и при проверке правил.

Перед каждой попыткой загрузки страницы проверяется разрешение из `robots.txt`. Запрещённые URL не запрашиваются, а блокировка записывается в лог и статистику. Адреса редиректов также проверяются. Загрузка самого `robots.txt` и повторы проходят через скоростной лимит.

Если `robots.txt` отсутствует (`404`), обход разрешается. При `401`, `403`, `429`, ошибках сервера или невозможности загрузить правила обход блокируется. Временные ошибки сначала проходят настроенные повторы.

Для HTTP `429`, `5xx`, ошибок соединения, чтения ответа и таймаутов используется экспоненциальный backoff. С настройками по умолчанию выполняются два повтора с паузами `0.5` и `1.0` секунды; максимальная пауза задаётся через `max_backoff=30.0`. Во время backoff соединения и семафоры освобождены. Постоянные ошибки, например `404`, не повторяются.

Подробный алгоритм, интерфейсы и ограничения описаны в [документации по ограничению скорости](docs/algorythms/rate_limiting.md).

## Очередь URL

Класс `CrawlerQueue` находится в файле:

```text
src/queues/crawler_queue.py
```

Очередь построена на основе `asyncio.PriorityQueue`.

Каждый элемент очереди содержит:

- приоритет;
- порядковый номер;
- URL.

Чем больше числовое значение приоритета, тем раньше URL будет получен из очереди.

Для URL с одинаковым приоритетом сохраняется порядок добавления.

Очередь отслеживает следующие состояния:

- ожидающие обработки URL;
- активные URL;
- успешно обработанные URL;
- неудачные URL.

Повторное добавление уже известного URL блокируется.

## Управление обходом

Основной обход запускается методом:

```python
results = await crawler.crawl(
    start_urls=["https://example.com"],
    max_pages=50,
    same_domain_only=True,
)
```

Алгоритм обхода:

1. Очищает состояние предыдущего запуска.
2. Проверяет стартовые URL.
3. Добавляет стартовые URL в очередь с глубиной `0`.
4. Получает из очереди очередную группу URL.
5. Загружает и парсит страницы конкурентно.
6. Помечает страницы как обработанные или неудачные.
7. Извлекает найденные ссылки.
8. Проверяет глубину каждой ссылки.
9. Применяет настроенные фильтры.
10. Исключает уже известные URL.
11. Добавляет подходящие ссылки в очередь.
12. Выводит текущую статистику.
13. Останавливается после достижения `max_pages` или опустошения очереди.

Если достигнут лимит `max_pages`, в очереди могут оставаться URL. Это нормальное поведение: они были найдены, но не были обработаны из-за установленного ограничения.

## Глубина обхода

Глубина стартового URL равна `0`.

Ссылки, найденные на стартовой странице, имеют глубину `1`.

Ссылки, найденные на страницах первого уровня, имеют глубину `2`.

Параметр `max_depth` определяет максимальную разрешённую глубину.

Пример:

```python
crawler = AsyncCrawler(max_depth=2)
```

В этом случае будут обработаны страницы с глубиной:

- `0`;
- `1`;
- `2`.

Ссылки с глубиной `3` и больше не добавляются в очередь.

## Фильтрация URL

Метод `crawl()` поддерживает несколько видов фильтрации.

### Только стартовые домены

```python
same_domain_only=True
```

При включённом параметре обрабатываются только URL, домены которых совпадают с доменами стартовых страниц.

### Исключаемые паттерны

```python
exclude_patterns=[
    "/login",
    "/logout",
    "/admin",
]
```

URL пропускается, если содержит хотя бы один исключаемый паттерн.

### Включаемые паттерны

```python
include_patterns=[
    "/docs/",
    "/articles/",
]
```

URL добавляется в очередь только в том случае, если содержит хотя бы один включаемый паттерн.

Проверка паттернов выполняется как поиск подстроки в URL.

## Состояние обхода

`AsyncCrawler` хранит:

- `visited_urls` — множество URL, взятых в обработку;
- `processed_urls` — успешно обработанные URL и полученные данные;
- `failed_urls` — URL, завершившиеся ошибкой, и причины ошибок.

Состояние очищается перед каждым новым вызовом `crawl()`.

Это позволяет повторно использовать один экземпляр краулера для нескольких независимых обходов.

## Статистика

Во время обхода отображаются:

- количество обработанных страниц;
- количество URL в очереди;
- количество ошибок;
- скорость обработки в страницах в секунду.

Статистика также доступна через:

```python
stats = crawler.get_crawl_stats()
```

Результат содержит:

- общее количество попыток обработки;
- количество успешных страниц;
- количество ожидающих URL;
- количество активных задач;
- количество ошибок;
- скорость обработки.

`get_crawl_stats()` также содержит статистику запросов, доступную отдельно через `get_request_stats()`:

- `requests` — количество HTTP-попыток, включая `robots.txt`, повторы и редиректы;
- `requests_per_second` — количество начал запросов за последнюю секунду;
- `average_delay` — средний фактический интервал между запросами в пределах одного скоростного лимита;
- `blocked` — количество уникальных URL, заблокированных правилами;
- `retries` — количество назначенных повторов.

Заблокированные URL входят в число неудачных страниц и дополнительно учитываются в `blocked`. Новый `crawl()` сбрасывает счётчики, сохраняя кэш правил и интервалы между запросами.

## Обработка ошибок

Краулер обрабатывает:

- HTTP-ошибки;
- сетевые ошибки;
- таймауты;
- некорректные URL;
- ошибки парсинга HTML.

Ошибка одной страницы не останавливает весь обход.

Неудачный URL помещается в `failed_urls`, а остальные страницы продолжают обрабатываться.

## Логирование

Программа логирует:

- начало загрузки URL;
- успешное завершение загрузки;
- HTTP-ошибки;
- сетевые ошибки;
- таймауты;
- начало парсинга;
- успешное завершение парсинга;
- предупреждения при обработке HTML.

Пример:

```text
Начало загрузки URL: https://example.com
Успешная загрузка URL: https://example.com
```


Тесты демонстрационной программы:

```bash
python -m pytest tests/test_main.py -v
```

Тесты сетевых операций используют локальный HTTP-сервер. Поэтому они не зависят от доступности внешних сайтов и скорости интернет-соединения.

Тесты ограничения скорости и правил обхода:

```bash
python -m pytest tests/concurrency/test_rate_limiter.py tests/parsers/test_robots_parser.py tests/crawler/test_politeness.py tests/test_main.py -v
```

Проверяются отдельные и глобальные лимиты, задержки, jitter, кэширование и парсинг правил, выбор User-Agent, запреты, редиректы, backoff, таймауты, статистика и локальная демонстрация в `main`.

На текущем этапе краулер:

- загружает страницы асинхронно;
