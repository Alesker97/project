# Банковская система

Учебный проект на Python для практики объектно-ориентированного программирования.

Проект представляет банковскую систему, которая позволяет управлять клиентами и счетами, выполнять переводы, обрабатывать очередь транзакций, рассчитывать комиссии и конвертировать валюты.

Все данные хранятся в памяти приложения. База данных и внешние API не используются.

## Возможности проекта

- создание клиентов банка;
- проверка возраста клиента;
- открытие банковских счетов;
- пополнение и снятие средств;
- накопительные счета с начислением процентов;
- премиальные счета с овердрафтом;
- инвестиционные счета с виртуальным портфелем;
- заморозка, разморозка и закрытие счетов;
- аутентификация клиентов;
- блокировка после трёх неверных попыток входа;
- фиксация подозрительных действий;
- ограничение операций со счетами в ночное время;
- поиск банковских счетов;
- расчёт общих балансов;
- формирование рейтинга клиентов;
- создание денежных транзакций;
- внутренние и внешние переводы;
- комиссии за внешние переводы;
- конвертация валют;
- приоритетная очередь транзакций;
- отложенные операции;
- отмена транзакций;
- повторные попытки при технических ошибках;
- журналирование ошибок обработки.

## Модель банковских счетов

### AbstractAccount

Абстрактный класс банковского счёта.

Содержит:

- уникальный номер счёта;
- данные владельца;
- защищённый баланс;
- валюту;
- статус счёта.

Определяет обязательные методы:

- `deposit()`;
- `withdraw()`;
- `get_account_info()`;
- `__str__()`.

### BankAccount

Базовая реализация банковского счёта.

Поддерживает:

- пополнение;
- снятие;
- проверку суммы;
- проверку статуса;
- запрет отрицательного баланса;
- автоматическую генерацию короткого UUID.

### SavingsAccount

Накопительный счёт.

Дополнительные возможности:

- минимальный допустимый остаток;
- месячная процентная ставка;
- начисление процентов методом `apply_monthly_interest()`.

После снятия баланс не может стать меньше установленного минимального остатка.

### PremiumAccount

Премиальный счёт.

Дополнительные возможности:

- увеличенный лимит снятия;
- разрешённый овердрафт;
- фиксированная комиссия за снятие.

Баланс может становиться отрицательным только в пределах установленного овердрафта.

### InvestmentAccount

Инвестиционный счёт с виртуальным портфелем.

Поддерживаемые типы активов:

- `stocks`;
- `bonds`;
- `etf`.

Метод `invest()` распределяет часть свободного баланса между активами.

Метод `project_yearly_growth()` рассчитывает ожидаемый годовой прирост портфеля на основании переданных ставок.

Проект использует упрощённую учебную модель. Реальные ценные бумаги, котировки и инвестиционные правила не применяются.

## Иерархия счетов

```text
AbstractAccount
└── BankAccount
    ├── SavingsAccount
    ├── PremiumAccount
    └── InvestmentAccount
```

Все дочерние классы переопределяют необходимое поведение, сохраняя единый интерфейс базового класса.

## Клиенты

Класс `Client` хранит:

- ФИО;
- уникальный идентификатор;
- возраст;
- контактные данные;
- статус;
- список номеров счетов.

Регистрация разрешена только клиентам в возрасте от 18 лет.

### Статусы клиентов

- `active` — клиент активен;
- `blocked` — клиент заблокирован.

После трёх последовательных неверных попыток входа клиент получает статус `blocked`.

## Управление банком

Класс `Bank` управляет клиентами и счетами.

Поддерживаемые методы:

- `add_client()` — добавление клиента;
- `open_account()` — открытие счёта;
- `close_account()` — закрытие счёта;
- `freeze_account()` — заморозка счёта;
- `unfreeze_account()` — разморозка счёта;
- `authenticate_client()` — аутентификация;
- `search_accounts()` — поиск счетов;
- `get_total_balance()` — расчёт балансов;
- `get_clients_ranking()` — рейтинг клиентов.

## Статусы счетов

- `active` — счёт активен;
- `frozen` — счёт заморожен;
- `closed` — счёт закрыт.

Пополнение и снятие доступны только для активных счетов.

## Безопасность

Банк фиксирует:

- неудачные попытки аутентификации;
- попытки управления счетами в запрещённое время.

Открытие, закрытие, заморозка и разморозка счетов запрещены с 00:00 до 05:00.

Ограничение по времени относится к операциям управления счетами. Обработка транзакций выполняется по правилам `TransactionProcessor`.

Пароли применяются только в рамках учебной модели и хранятся в памяти приложения.

## Аналитика

### Общий баланс

Метод `get_total_balance()` возвращает остатки на счетах, сгруппированные по валютам.

Стоимость инвестиционного портфеля не включается в свободный баланс инвестиционного счёта.

### Рейтинг клиентов

Метод `get_clients_ranking()` формирует рейтинг клиентов по сумме средств в выбранной валюте.

Суммы разных валют не складываются без предварительной конвертации.

## Модель транзакции

Класс `Transaction` представляет перевод между двумя банковскими счетами.

Транзакция содержит:

- уникальный идентификатор;
- тип;
- сумму;
- валюту;
- комиссию;
- отправителя;
- получателя;
- статус;
- причину отказа или отмены;
- время создания;
- запланированное время;
- время завершения;
- количество попыток.

Если идентификатор не передан, автоматически создаётся короткий UUID.

### Типы транзакций

- `internal_transfer` — внутренний перевод;
- `external_transfer` — внешний перевод с комиссией.

### Статусы транзакций

- `pending` — ожидает обработки;
- `processing` — обрабатывается;
- `completed` — успешно завершена;
- `failed` — завершена с ошибкой;
- `cancelled` — отменена.

## Очередь транзакций

Класс `TransactionQueue` поддерживает:

- добавление транзакций;
- проверку дублирования;
- приоритеты;
- порядок добавления;
- отложенные операции;
- отмену ожидающих транзакций.

### Приоритеты

- `LOW`;
- `NORMAL`;
- `HIGH`.

Сначала выбирается доступная транзакция с наибольшим приоритетом.

При одинаковом приоритете первой обрабатывается транзакция, которая была добавлена раньше.

Отложенная операция не выполняется до наступления её `scheduled_at`, независимо от приоритета.

## Обработка транзакций

Класс `TransactionProcessor` отвечает за:

- проверку счетов;
- расчёт комиссий;
- конвертацию валют;
- списание и зачисление средств;
- повторные попытки;
- изменение статусов;
- фиксацию ошибок;
- обработку очереди.

### Проверки

Перевод запрещается, если:

- счёт отправителя заморожен;
- счёт получателя заморожен;
- один из счетов закрыт;
- валюта транзакции не совпадает с валютой отправителя;
- отсутствует курс конвертации;
- недостаточно средств;
- обычный счёт имеет отрицательный баланс.

Для списания вызывается метод `withdraw()` конкретного типа счёта.

Благодаря полиморфизму:

- обычный счёт не может уйти в минус;
- накопительный счёт сохраняет минимальный остаток;
- премиальный счёт может использовать овердрафт;
- инвестиционный счёт использует свободный баланс.

## Комиссии

Внутренний перевод не имеет комиссии.

Комиссия внешнего перевода рассчитывается по формуле:

`commission = amount × external_commission_rate`

Со счёта отправителя списываются сумма перевода и комиссия.

Получателю зачисляется сумма перевода без вычитания комиссии.

Если отправителем является `PremiumAccount`, отдельно применяется фиксированная комиссия самого премиального счёта.

## Конвертация валют

Курсы передаются в `TransactionProcessor` в виде словаря:

```python
conversion_rates = {
    (Currency.USD, Currency.RUB): Decimal("80"),
    (Currency.RUB, Currency.USD): Decimal("0.0125"),
}
```

Если валюты счетов отличаются, сумма получателя рассчитывается по формуле:

`recipient_amount = amount × conversion_rate`

Результат округляется до двух знаков по правилу `ROUND_HALF_UP`.

Реальные курсы валют и внешние API не используются.

## Повторные попытки

Параметр `max_retries` задаёт количество повторов после первой попытки.

Логические ошибки не повторяются:

- замороженный счёт;
- закрытый счёт;
- недостаточно средств;
- отсутствующий курс;
- некорректная операция.

Неожиданные технические ошибки повторяются до исчерпания разрешённого количества попыток.

## Журнал ошибок

Ошибки обработки сохраняются в `error_log`.

Каждая запись содержит:

- идентификатор транзакции;
- номер попытки;
- текст ошибки;
- время ошибки.

Журнал хранится в памяти приложения.

## Валюты

Поддерживаются:

- `RUB`;
- `USD`;
- `EUR`;
- `KZT`;
- `CNY`.

Без явно переданного курса автоматическая конвертация не выполняется.

## Исключения

В проекте используются собственные исключения:

- `AccountFrozenError` — счёт заморожен;
- `AccountClosedError` — счёт закрыт;
- `InvalidOperationError` — операция или данные некорректны;
- `InsufficientFundsError` — недостаточно средств.

## Установка

Клонировать репозиторий:

```bash
git clone <URL-репозитория>
```

Перейти в папку проекта:

```bash
cd <название-папки>
```

Создать виртуальное окружение:

```bash
python -m venv .venv
```

Активировать виртуальное окружение в PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установить зависимости:

```bash
python -m pip install -r requirements.txt
```

- отказ при работе с замороженными счетами;
- отказ при недостатке средств;
- отложенную транзакцию;
- отмену транзакции;
