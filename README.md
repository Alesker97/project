# Banking System

Учебный проект банковской системы, созданный для практики объектно-ориентированного программирования на Python.

Система поддерживает клиентов, банковские счета разных типов, транзакции, очереди операций, комиссии, конвертацию валют, аудит и анализ рисков.

## Возможности проекта

### Банковские счета

В проекте реализован абстрактный класс `AbstractAccount` и следующие типы счетов:

- `BankAccount` — базовый банковский счёт;
- `SavingsAccount` — накопительный счёт с минимальным остатком и месячной ставкой;
- `PremiumAccount` — премиальный счёт с увеличенным лимитом, овердрафтом и фиксированной комиссией;
- `InvestmentAccount` — инвестиционный счёт с портфелем из акций, облигаций и ETF.

Каждый счёт содержит:

- уникальный идентификатор;
- владельца;
- защищённый баланс;
- валюту;
- статус;
- методы пополнения и снятия;
- строковое представление;
- получение полной информации о счёте.

Поддерживаемые валюты:

- RUB;
- USD;
- EUR;
- KZT;
- CNY.

Поддерживаемые статусы счетов:

- `active`;
- `frozen`;
- `closed`.

### Клиенты

Класс `Client` содержит:

- ФИО;
- идентификатор клиента;
- возраст;
- контактные данные;
- статус;
- список номеров счетов.

Регистрация разрешена только клиентам не младше 18 лет.

### Банк

Класс `Bank` управляет клиентами и счетами.

Реализованы операции:

- добавление клиента;
- открытие счёта;
- закрытие счёта;
- заморозка счёта;
- разморозка счёта;
- аутентификация клиента;
- поиск счетов;
- обработка транзакций;
- расчёт общего баланса;
- формирование рейтинга клиентов.

После трёх неверных попыток аутентификации клиент блокируется.

Подозрительные действия сохраняются в памяти банка.

### Транзакции

Класс `Transaction` содержит:

- идентификатор;
- тип;
- сумму;
- валюту;
- комиссию;
- отправителя;
- получателя;
- статус;
- причину отказа;
- время создания, начала и завершения.

Поддерживаются внутренние и внешние переводы.

Статусы транзакций:

- `pending`;
- `processing`;
- `completed`;
- `failed`;
- `cancelled`.

### Очередь транзакций

Класс `TransactionQueue` поддерживает:

- добавление транзакций;
- приоритеты;
- отложенное выполнение;
- отмену транзакций;
- получение следующей доступной транзакции.

Приоритеты:

- `high`;
- `normal`;
- `low`.

Сначала обрабатываются транзакции с более высоким приоритетом. При одинаковом приоритете сохраняется порядок добавления.

Отложенная транзакция остаётся в очереди до наступления времени, указанного в `scheduled_at`.

### Обработка транзакций

Класс `TransactionProcessor` выполняет:

- проверку статусов счетов;
- проверку времени операции;
- проверку валют;
- расчёт комиссии;
- конвертацию валют;
- снятие средств;
- зачисление средств;
- повторные попытки;
- фиксацию ошибок.

Внешний перевод облагается процентной комиссией.

При переводе между счетами с разными валютами используется настроенный курс конвертации.

Логические ошибки не повторяются. К ним относятся:

- замороженный счёт;
- закрытый счёт;
- недостаток средств;
- нарушение ограничений счёта;
- запрещённое время операции;
- некорректная операция.

Непредвиденные технические ошибки могут быть повторены в пределах `max_retries`.

### Атомарность переводов

Перед каждой попыткой перевода процессор сохраняет балансы отправителя и получателя.

Если после снятия средств возникает ошибка при пополнении получателя, процессор восстанавливает оба баланса до состояния перед попыткой.

Поэтому повторная попытка не приводит к повторному списанию средств.

Атомарность реализована для текущей учебной модели, работающей в памяти приложения.

### Ночные ограничения

С `00:00` включительно до `05:00` исключительно запрещены:

- открытие счетов;
- закрытие счетов;
- заморозка счетов;
- разморозка счетов;
- банковские переводы.

Ночной перевод блокируется независимо от суммы и рассчитанного уровня риска.

Проверка выполняется:

- в `Bank` до передачи транзакции процессору;
- в `TransactionProcessor` перед изменением балансов.

Дополнительная проверка в процессоре защищает систему при его прямом использовании без класса `Bank`.

### Аудит

Класс `AuditLog` сохраняет события:

- в памяти приложения;
- в файл формата JSON Lines.

Уровни аудита:

- `info`;
- `warning`;
- `error`;
- `critical`.

Поддерживается фильтрация записей по:

- уровню;
- типу события;
- идентификатору клиента;
- идентификатору транзакции.

Основные типы событий:

- `transaction_requested`;
- `risk_assessment`;
- `transaction_completed`;
- `transaction_failed`;
- `transaction_blocked`.

По умолчанию файловый журнал демонстрационной программы сохраняется в:

```text
logs/audit.jsonl
```

Каждая строка файла содержит отдельную запись аудита в формате JSON.

### Анализ рисков

Класс `RiskAnalyzer` определяет следующие признаки:

- `large_amount` — крупная сумма;
- `frequent_operations` — частые операции;
- `new_recipient` — перевод на новый счёт;
- `night_operation` — операция в ночное время.

Уровни риска:

- `low`;
- `medium`;
- `high`.

Правила расчёта:

- ни одного признака — низкий риск;
- один признак — средний риск;
- два и более признака — высокий риск.

Транзакции с высоким уровнем риска блокируются банком до изменения балансов.

Ночная операция блокируется всегда, даже если по совокупности признаков она получила низкий или средний уровень риска.

### Отчёты аудита

Класс `AuditReport` формирует:

- список подозрительных транзакций;
- риск-профиль клиента;
- статистику ошибок.

Риск-профиль содержит:

- общее количество операций;
- количество операций каждого уровня риска;
- количество заблокированных операций;
- максимальный обнаруженный уровень риска.

## Требования

- Python 3.10 или новее;
- pytest 9.1.1.

## Установка

Создать виртуальное окружение:

```powershell
python -m venv .venv
```

Активировать его в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

## Запуск демонстрации

Из корневой папки проекта выполнить:

```powershell
python -m src.main
```

Демонстрационная программа показывает:

- создание клиентов и счетов;
- работу разных типов счетов;
- аутентификацию;
- блокировку клиента;
- операции со счетами;
- очередь транзакций;
- приоритетные и отложенные транзакции;
- отмену транзакции;
- комиссии;
- конвертацию валют;
- ошибочные переводы;
- блокировку замороженных счетов;
- ночные ограничения;
- аудит;
- анализ рисков;
- блокировку опасных операций;
- отчёты аудита.

## Запуск тестов

Запустить все тесты:

```powershell
pytest
```

Запустить отдельную группу тестов:

```powershell
pytest tests/transactions
```

Запустить отдельный файл:

```powershell
pytest tests/transactions/test_transaction_processor.py
```

Подробный вывод:

```powershell
pytest -v
```

## Основные правила системы

- сумма операции должна быть положительной;
- операции по закрытым и замороженным счетам запрещены;
- обычные счета не могут уходить в отрицательный баланс;
- накопительный счёт должен сохранять минимальный остаток;
- премиальный счёт может использовать разрешённый овердрафт;
- внешние переводы облагаются комиссией;
- при разных валютах применяется курс конвертации;
- частично выполненный перевод откатывается перед повторной попыткой;
- с `00:00` до `05:00` переводы запрещены;
- транзакции высокого риска блокируются;
- ошибки и результаты риск-анализа фиксируются в журнале аудита.
