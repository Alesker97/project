# Banking System

Учебная банковская система на Python для практики объектно-ориентированного программирования.

Проект моделирует клиентов, банковские счета, переводы, очередь транзакций, комиссии, валютную конвертацию, безопасность, аудит и анализ рисков.

Данные хранятся в памяти приложения. База данных и внешние API не используются.

## Возможности проекта

### Банковские счета

В проекте реализован абстрактный класс `AbstractAccount` и четыре типа счетов:

- `BankAccount` — базовый банковский счёт;
- `SavingsAccount` — накопительный счёт;
- `PremiumAccount` — премиальный счёт;
- `InvestmentAccount` — инвестиционный счёт.

Каждый счёт содержит:

- уникальный идентификатор;
- владельца;
- защищённый баланс;
- валюту;
- статус;
- операции пополнения и снятия;
- получение информации о счёте;
- строковое представление.

Поддерживаемые валюты:

- RUB;
- USD;
- EUR;
- KZT;
- CNY.

Статусы счетов:

- `active`;
- `frozen`;
- `closed`.

### Накопительный счёт

`SavingsAccount` поддерживает:

- минимальный остаток;
- месячную ставку;
- начисление процентов;
- запрет снятия, нарушающего минимальный остаток.

### Премиальный счёт

`PremiumAccount` поддерживает:

- увеличенный лимит снятия;
- разрешённый овердрафт;
- фиксированную комиссию;
- снятие средств в пределах доступного овердрафта.

### Инвестиционный счёт

`InvestmentAccount` содержит инвестиционный портфель.

Поддерживаемые виртуальные активы:

- `stocks`;
- `bonds`;
- `etf`.

Реализованы:

- добавление средств в актив;
- проверка доступности средств;
- расчёт стоимости портфеля;
- прогноз ожидаемого годового прироста.

## Клиенты

Класс `Client` содержит:

- ФИО;
- уникальный идентификатор;
- возраст;
- контактные данные;
- статус;
- список номеров счетов.

Клиент должен быть не младше 18 лет.

Статусы клиента:

- `active`;
- `blocked`.

## Банк

Класс `Bank` управляет клиентами, счетами и транзакциями.

Основные операции:

- добавление клиента;
- открытие счёта;
- закрытие счёта;
- заморозка счёта;
- разморозка счёта;
- аутентификация клиента;
- поиск счетов;
- обработка транзакций;
- расчёт общего баланса;
- построение рейтинга клиентов.

После трёх неверных попыток аутентификации клиент блокируется.

Подозрительные действия сохраняются в памяти банка.

## Транзакции

Класс `Transaction` содержит:

- идентификатор;
- тип;
- сумму;
- валюту;
- комиссию;
- отправителя;
- получателя;
- статус;
- причину отказа;
- время создания;
- запланированное время;
- время начала обработки;
- время завершения.

Типы транзакций:

- `internal_transfer`;
- `external_transfer`.

Статусы транзакций:

- `pending`;
- `processing`;
- `completed`;
- `failed`;
- `cancelled`.

## Очередь транзакций

`TransactionQueue` поддерживает:

- добавление транзакций;
- приоритеты;
- отложенные операции;
- отмену;
- получение следующей доступной транзакции.

Приоритеты:

- `high`;
- `normal`;
- `low`.

Сначала обрабатываются доступные транзакции с более высоким приоритетом.

При одинаковом приоритете сохраняется порядок добавления.

Транзакция с будущим `scheduled_at` остаётся в очереди до наступления заданного времени.

## Обработка транзакций

`TransactionProcessor` выполняет:

- проверку времени;
- проверку статусов счетов;
- проверку баланса;
- проверку ограничений конкретного типа счёта;
- расчёт комиссии;
- конвертацию валют;
- списание;
- зачисление;
- повторные попытки;
- фиксацию ошибок.

Для внешнего перевода рассчитывается процентная комиссия.

При переводе между разными валютами используется настроенный курс конвертации.

## Повторные попытки

Логические ошибки не повторяются:

- замороженный счёт;
- закрытый счёт;
- недостаток средств;
- нарушение минимального остатка;
- превышение лимита;
- отсутствие курса конвертации;
- запрещённое время операции;
- другая некорректная операция.

Непредвиденные технические ошибки могут повторяться в пределах `max_retries`.

Максимальное количество попыток:

`1 + max_retries`

Каждая ошибка сохраняется в `error_log`.

## Атомарность переводов

Перед каждой попыткой перевода процессор сохраняет:

- баланс отправителя;
- баланс получателя.

Если списание прошло успешно, но зачисление завершилось ошибкой, оба баланса восстанавливаются.

Повторная попытка начинается с исходного состояния счетов и не приводит к повторному списанию средств.

Атомарность реализована для текущей учебной модели, работающей в памяти приложения.

## Ночные ограничения

С `00:00` включительно до `05:00` исключительно запрещены:

- открытие счёта;
- закрытие счёта;
- заморозка счёта;
- разморозка счёта;
- выполнение банковского перевода.

Ночной перевод блокируется независимо от суммы и рассчитанного уровня риска.

Проверка выполняется на двух уровнях:

1. `Bank` блокирует операцию до передачи процессору.
2. `TransactionProcessor` повторно проверяет время перед изменением балансов.

Дополнительная проверка процессора защищает систему при его прямом использовании без `Bank`.

## Аудит

`AuditLog` сохраняет события:

- в памяти приложения;
- в файл формата JSON Lines.

Уровни аудита:

- `info`;
- `warning`;
- `error`;
- `critical`.

Поддерживается фильтрация по:

- уровню;
- типу события;
- идентификатору клиента;
- идентификатору транзакции.

Основные типы событий:

- `transaction_requested`;
- `risk_assessment`;
- `transaction_completed`;
- `transaction_failed`;
- `transaction_blocked`.

Файл аудита:

`logs/audit.jsonl`

Каждая строка содержит отдельную JSON-запись.

## Анализ рисков

`RiskAnalyzer` проверяет следующие признаки:

- `large_amount` — крупная сумма;
- `frequent_operations` — частые операции;
- `new_recipient` — новый получатель;
- `night_operation` — ночная операция.

Уровни риска:

- `low`;
- `medium`;
- `high`.

Правила расчёта:

- нет признаков — низкий риск;
- один признак — средний риск;
- два и более признака — высокий риск.

Транзакции высокого риска блокируются до изменения балансов.

Ночная операция блокируется всегда, даже если рассчитанный уровень риска является низким или средним.

## Отчёты аудита

`AuditReport` формирует:

- список подозрительных операций;
- риск-профиль клиента;
- статистику ошибок.

Риск-профиль клиента содержит:

- общее количество операций;
- количество операций каждого уровня риска;
- количество заблокированных операций;
- максимальный обнаруженный уровень риска.

## Демонстрационная программа

## Основные правила системы

- сумма операции должна быть положительной;
- операции по закрытым счетам запрещены;
- операции по замороженным счетам запрещены;
- обычный счёт не может иметь отрицательный баланс;
- накопительный счёт должен сохранять минимальный остаток;
- премиальный счёт может использовать разрешённый овердрафт;
- премиальный счёт применяет фиксированную комиссию;
- внешний перевод облагается процентной комиссией;
- при разных валютах применяется настроенный курс;
- без курса конвертации перевод отклоняется;
- частично выполненный перевод полностью откатывается;
- повторная попытка не списывает деньги повторно;
- с `00:00` до `05:00` переводы запрещены;
- транзакции высокого риска блокируются;
- ошибки и блокировки сохраняются в аудите.
