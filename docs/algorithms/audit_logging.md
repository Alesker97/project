# Журнал аудита

## Назначение

Класс `AuditLog` фиксирует события банковской системы.

Журнал поддерживает:

- хранение записей в памяти;
- сохранение записей в файл;
- уровни важности;
- фильтрацию по нескольким параметрам;
- преобразование специальных типов в JSON.

## Уровни важности

Поддерживаются следующие уровни:

- `info` — обычное информационное событие;
- `warning` — событие, требующее внимания;
- `error` — ошибка выполнения операции;
- `critical` — критическое событие или блокировка.

## Структура записи

Каждая запись содержит:

- время события;
- уровень важности;
- тип события;
- текст сообщения;
- идентификатор клиента;
- идентификатор транзакции;
- дополнительные данные.

Идентификаторы клиента и транзакции могут отсутствовать, если событие с ними не связано.

Дополнительные данные хранятся в словаре `details`.

## Добавление записи

Метод `log()` выполняет следующие действия:

1. Проверяет уровень аудита.
2. Проверяет тип события.
3. Проверяет сообщение.
4. Проверяет идентификаторы клиента и транзакции.
5. Проверяет дополнительные данные.
6. Получает время события.
7. Создаёт запись аудита.
8. Сохраняет запись в файл, если указан путь.
9. Добавляет запись в память.
10. Возвращает копию созданной записи.

Если запись не удалось сохранить в файл, возникает `InvalidOperationError`.

## Хранение в памяти

Записи сохраняются во внутреннем списке.

Свойство `entries` возвращает глубокую копию списка. Изменение полученной копии не изменяет исходный журнал.

Метод `len()` возвращает количество записей в памяти.

## Сохранение в файл

Для файлового хранения используется формат JSON Lines.

Каждая строка файла `logs/audit.jsonl` содержит отдельный JSON-объект.

Новые записи добавляются в конец файла. Существующее содержимое не перезаписывается.

Перед сохранением автоматически создаётся родительская папка, если она отсутствует.

## Преобразование значений

При записи в JSON выполняются преобразования:

- `datetime` преобразуется в строку ISO 8601;
- `Decimal` преобразуется в строку;
- `Enum` преобразуется в его значение;
- кортеж преобразуется в список;
- вложенные словари и списки обрабатываются рекурсивно.

В памяти сохраняются исходные типы объектов.

## Фильтрация

Метод `filter()` позволяет фильтровать записи по:

- уровню важности;
- типу события;
- идентификатору клиента;
- идентификатору транзакции;
- начальному времени;
- конечному времени.

Фильтры можно комбинировать.

Начальное время не может быть позже конечного.

Метод возвращает глубокую копию найденных записей.

## Типы событий

При обработке банковских транзакций используются события:

- `transaction_requested` — получен запрос;
- `risk_assessment` — выполнена оценка риска;
- `transaction_completed` — операция выполнена;
- `transaction_failed` — операция завершилась ошибкой;
- `transaction_blocked` — операция заблокирована банком.
