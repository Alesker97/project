# Обработка транзакций

## Назначение

Класс `TransactionProcessor` выполняет денежные переводы между счетами.

Процессор отвечает за:

- проверку счетов;
- расчёт комиссии;
- конвертацию валют;
- списание и зачисление средств;
- повторные попытки;
- изменение статуса транзакции;
- фиксацию ошибок;
- обработку очереди.

## Обработка одной транзакции

Метод `process()` выполняет следующие действия:

1. Проверяет тип объекта.
2. Проверяет, что транзакция имеет статус `pending`.
3. Устанавливает статус `processing`.
4. Увеличивает количество попыток.
5. Проверяет статусы счетов.
6. Проверяет возможность перевода с текущего баланса.
7. Проверяет валюту транзакции.
8. Рассчитывает комиссию.
9. Определяет сумму зачисления получателю.
10. Списывает сумму и комиссию у отправителя.
11. Зачисляет средства получателю.
12. Устанавливает итоговый статус.
13. Записывает время завершения.

Метод возвращает `True` при успешном выполнении и `False` при отказе.

## Проверка счетов

До списания средств проверяются оба счёта.

Перевод запрещается, если:

- счёт отправителя заморожен;
- счёт получателя заморожен;
- счёт отправителя закрыт;
- счёт получателя закрыт;
- обычный счёт имеет отрицательный баланс;
- валюта транзакции не совпадает с валютой отправителя;
- отсутствует необходимый курс конвертации;
- на счёте недостаточно средств.

Основные проверки выполняются до изменения баланса отправителя.

## Проверка баланса

Для списания используется полиморфный метод `withdraw()` конкретного типа счёта.

Поэтому применяются правила соответствующего класса:

- `BankAccount` запрещает отрицательный баланс;
- `SavingsAccount` сохраняет минимальный остаток;
- `PremiumAccount` разрешает овердрафт в пределах лимита;
- `InvestmentAccount` использует свободный баланс счёта.

Логика счетов не дублируется внутри процессора.

## Комиссия

Внутренний перевод не имеет комиссии:

`commission = 0`

Для внешнего перевода применяется переданная ставка:

`commission = amount × external_commission_rate`

Комиссия округляется до двух знаков.

Со счёта отправителя списываются:

`amount + commission`

Получатель получает сумму перевода без вычитания комиссии.

Если отправителем является `PremiumAccount`, дополнительно применяется фиксированная комиссия самого премиального счёта.

## Конвертация валют

Если валюты счетов совпадают, получателю зачисляется исходная сумма.

Если валюты различаются, процессор ищет курс по паре:

`валюта отправителя → валюта получателя`

Сумма зачисления рассчитывается следующим образом:

`recipient_amount = amount × conversion_rate`

Результат округляется до двух знаков по правилу `ROUND_HALF_UP`.

Если курс отсутствует, транзакция завершается со статусом `failed`.

Курсы передаются в процессор вручную. Внешние API и реальные котировки не используются.

## Повторные попытки

Параметр `max_retries` определяет количество повторов после первой попытки.

Общее максимальное количество попыток:

`1 + max_retries`

Логические ошибки не повторяются:

- замороженный счёт;
- закрытый счёт;
- недостаточно средств;
- некорректная операция;
- отсутствующий курс.

Неожиданные технические ошибки повторяются до исчерпания разрешённого количества попыток.

При успешной повторной попытке транзакция получает статус `completed`.

Если все попытки завершились ошибкой, устанавливается статус `failed`.

## Журнал ошибок

Каждая ошибка добавляется в `error_log`.

Запись содержит:

- идентификатор транзакции;
- номер попытки;
- текст ошибки;
- время возникновения ошибки.

Журнал хранится в памяти приложения.

## Обработка очереди

Метод `process_next()` получает из очереди одну доступную транзакцию и обрабатывает её.

Если доступных транзакций нет, возвращается `None`.

Метод `process_all()` последовательно вызывает `process_next()` до тех пор, пока в очереди остаются доступные операции.

Отложенные транзакции остаются в очереди до наступления установленного времени.
