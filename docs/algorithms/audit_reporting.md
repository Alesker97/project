# Отчёты аудита

## Назначение

Класс `AuditReport` формирует отчёты на основании записей `AuditLog`.

Исходный журнал при формировании отчётов не изменяется.

Поддерживаются:

- отчёт по подозрительным операциям;
- риск-профиль клиента;
- статистика ошибок.

## Подозрительные операции

Метод `get_suspicious_operations()` выбирает записи типа `risk_assessment`.

В отчёт включаются операции с уровнями:

- `medium`;
- `high`.

Операции уровня `low` в отчёт не включаются.

Для каждой операции доступны:

- идентификатор клиента;
- идентификатор транзакции;
- уровень риска;
- причины риска;
- сумма;
- валюта;
- номер счёта получателя;
- время анализа.

## Риск-профиль клиента

Метод `get_client_risk_profile()` формирует профиль по идентификатору клиента.

Профиль содержит:

- идентификатор клиента;
- общее количество оценённых операций;
- количество операций низкого риска;
- количество операций среднего риска;
- количество операций высокого риска;
- количество заблокированных операций;
- максимальный обнаруженный уровень риска.

Если у клиента нет оценённых операций:

- количество операций равно нулю;
- максимальный уровень риска имеет значение `None`.

## Статистика ошибок

Метод `get_error_statistics()` анализирует записи уровней:

- `error`;
- `critical`.

Результат содержит:

- общее количество ошибок;
- количество записей по каждому типу события.

Оценка высокого риска имеет уровень `critical`.

Блокировка опасной операции также имеет уровень `critical`.

Поэтому одна заблокированная операция создаёт две критические записи:

1. `risk_assessment`;
2. `transaction_blocked`.

Ошибка разрешённой транзакции создаёт запись уровня `error` с типом `transaction_failed`.

## Хранение отчётов

Отчёты формируются по данным, находящимся в памяти.

Они не сохраняются в отдельные файлы и не изменяют `logs/audit.jsonl`.

При необходимости полученные словари и списки можно передать другому слою приложения для вывода или дальнейшей обработки.
