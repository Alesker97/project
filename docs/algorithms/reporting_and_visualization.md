# Отчётность и визуализация

## Назначение

Система отчётности формирует сводные данные о клиентах, банке, транзакциях и рисках, экспортирует их в текстовый, JSON и CSV форматы, а также сохраняет диаграммы в формате PNG.

Основным компонентом системы является класс `ReportBuilder`.

## Исходные данные

`ReportBuilder` получает:

- объект банка;
- словарь клиентов;
- список транзакций;
- объект аудиторского отчёта;
- журнал обработки транзакций.

Класс не изменяет банковские данные и использует их только для формирования отчётов и диаграмм.

## Отчёт по клиенту

Метод `build_client_report()` формирует отчёт по выбранному клиенту.

Отчёт содержит:

- ID клиента;
- ФИО;
- возраст;
- статус;
- контакты;
- список счетов;
- баланс по каждой валюте;
- количество входящих и исходящих транзакций;
- статистику транзакций по статусам;
- сумму комиссий;
- историю операций;
- риск-профиль;
- подозрительные операции клиента.

Направление транзакции определяется относительно счетов клиента:

- `incoming` — входящая операция;
- `outgoing` — исходящая операция;
- `internal` — перевод между счетами одного клиента.

## Отчёт по банку

Метод `build_bank_report()` формирует общий отчёт банковской системы.

Отчёт содержит:

- количество клиентов;
- количество счетов;
- распределение счетов по типам;
- распределение счетов по статусам;
- распределение счетов по валютам;
- общий баланс по каждой валюте;
- количество транзакций;
- распределение транзакций по статусам;
- количество выполненных операций;
- количество отклонённых операций;
- количество отменённых операций;
- количество операций, заблокированных банком;
- количество ошибок процессора;
- сумму полученных комиссий;
- трёх клиентов с наибольшим балансом в RUB;
- подозрительные действия;
- количество записей аудита.

## Отчёт по рискам

Метод `build_risk_report()` формирует отчёт по результатам риск-анализа.

Отчёт содержит:

- список подозрительных операций;
- количество операций по уровням риска;
- количество причин риска каждого типа;
- количество заблокированных операций;
- риск-профили клиентов;
- статистику ошибок аудита.

Используются уровни риска:

- `low`;
- `medium`;
- `high`.

Учитываются следующие причины риска:

- крупная сумма;
- частые операции;
- перевод на новый счёт;
- операция в запрещённое ночное время.

## Текстовый отчёт

Метод `build_text_report()` преобразует вложенную структуру отчёта в многострочный текст.

Вложенные словари и списки отображаются с отступами. Значения `Decimal`, `Enum`, `datetime` и `Path` предварительно преобразуются в строковый формат.

## Экспорт в JSON

Метод `export_to_json()` сохраняет отчёт в JSON-файл.

Перед сохранением выполняются следующие преобразования:

- `Decimal` преобразуется в строку;
- `Enum` преобразуется в значение перечисления;
- `datetime` преобразуется в ISO-формат;
- `Path` преобразуется в строку;
- вложенные словари и списки обрабатываются рекурсивно.

Файл сохраняется в кодировке UTF-8. Русские символы записываются без Unicode-последовательностей.

## Экспорт в CSV

Метод `export_to_csv()` сохраняет отчёт в CSV-файл с колонками:

- `field`;
- `value`.

Вложенные словари преобразуются в поля с точечной нотацией.

Пример:

```text
transactions.by_status.completed
```

Списки сохраняются как JSON-строки внутри CSV.

## Диаграммы

Метод `save_charts()` сохраняет три диаграммы.

### Круговая диаграмма

Файл:

```text
transaction_statuses_pie.png
```

Диаграмма показывает распределение транзакций по итоговым статусам:

- `completed`;
- `failed`;
- `cancelled`.

Статусы с нулевым количеством операций не отображаются.

### Столбчатая диаграмма

Файл:

```text
client_balances_bar.png
```

Диаграмма показывает итоговые балансы клиентов в выбранной валюте.

По умолчанию используется валюта RUB.

### График движения баланса

Файл:

```text
account_balance_history.png
```

График показывает изменение баланса выбранного счёта во время обработки транзакций.

Для каждой обработанной операции журнал содержит:

- номер счёта отправителя;
- номер счёта получателя;
- баланс отправителя до операции;
- баланс отправителя после операции;
- баланс получателя до операции;
- баланс получателя после операции;
- время обработки.

Неисполненные и заблокированные операции также попадают в журнал, но их баланс до и после обработки остаётся одинаковым.

## Хранение результатов

При запуске демонстрационной программы автоматически создаётся следующая структура:

```text
output/
├── reports/
│   ├── client_report.json
│   ├── client_report.csv
│   ├── bank_report.json
│   ├── bank_report.csv
│   ├── risk_report.json
│   └── risk_report.csv
└── charts/
    ├── transaction_statuses_pie.png
    ├── client_balances_bar.png
    └── account_balance_history.png
```

Каталоги создаются автоматически. При повторном запуске файлы с одинаковыми именами перезаписываются актуальными результатами.

Каталог `output/` добавлен в `.gitignore`, поскольку содержит генерируемые файлы.

## Интеграция с демонстрационной программой

После выполнения симуляции `DemoRunner`:

1. формирует отчёт по клиенту;
2. формирует отчёт по банку;
3. формирует отчёт по рискам;
4. выводит текстовый отчёт по клиенту;
5. сохраняет отчёты в JSON;
6. сохраняет отчёты в CSV;
7. создаёт три диаграммы;
8. выводит пути созданных файлов.

Точка входа проекта остаётся неизменной:

```powershell
python -m src.main
```

## Тестирование

Тесты проверяют:

- формирование отчёта по клиенту;
- формирование отчёта по банку;
- формирование отчёта по рискам;
- создание текстового отчёта;
- корректность JSON-файла;
- корректность CSV-файла;
- автоматическое создание директорий;
- создание трёх PNG-файлов;
- наличие данных в созданных файлах;
- интеграцию отчётности с `DemoRunner`.

Для запуска тестов отчётности используется команда:

```powershell
python -m pytest tests/reports/test_report_builder.py -v
```

Для запуска всех тестов используется команда:

```powershell
python -m pytest
```
