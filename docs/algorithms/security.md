# Безопасность

## Аутентификация клиента

Банк хранит пароль, связанный с идентификатором клиента.

Метод `authenticate_client()` проверяет:

- существование клиента;
- текущий статус клиента;
- соответствие переданного пароля сохранённому.

При успешной аутентификации:

- счётчик неверных попыток сбрасывается;
- метод возвращает `True`.

При неверном пароле:

- счётчик неверных попыток увеличивается;
- действие фиксируется как подозрительное;
- метод возвращает `False`.

После трёх неверных попыток клиент получает статус `blocked`.

Заблокированный клиент не может пройти аутентификацию.

## Подозрительные действия

Банк хранит подозрительные действия в памяти приложения.

Запись содержит:

- идентификатор клиента;
- тип действия;
- timestamp.

К подозрительным действиям относятся:

- неверная аутентификация;
- попытка выполнить запрещённую ночную операцию со счётом;
- попытка выполнить ночной перевод.

## Ограничения по статусу счёта

Счёт может иметь один из следующих статусов:

- `active`;
- `frozen`;
- `closed`.

Операции разрешены только для активного счёта.

Замороженный счёт сохраняется в системе, но не может участвовать в пополнениях, снятиях и переводах.

Закрытый счёт не может использоваться для дальнейших операций.

## Ограничение по времени

С `00:00` включительно до `05:00` исключительно запрещены:

- открытие счёта;
- закрытие счёта;
- заморозка счёта;
- разморозка счёта;
- выполнение перевода.

Запрещённая операция не должна изменять состояние счетов.

Попытка выполнить такую операцию сохраняется как подозрительное действие.

## Защита переводов

Перевод проходит несколько уровней проверки:

1. `Bank` проверяет существование клиента.
2. `Bank` проверяет регистрацию счёта отправителя.
3. `Bank` проверяет принадлежность счёта отправителя клиенту.
4. `RiskAnalyzer` определяет признаки и уровень риска.
5. `Bank` безусловно блокирует ночную операцию.
6. `Bank` блокирует операцию с высоким уровнем риска.
7. Разрешённая транзакция передаётся в `TransactionProcessor`.
8. `TransactionProcessor` повторно проверяет время.
9. Процессор проверяет статусы счетов.
10. Процессор проверяет ограничения баланса.
11. Только после успешного прохождения проверок изменяются балансы.

Двойная проверка времени необходима, потому что `TransactionProcessor` может использоваться напрямую без класса `Bank`.

## Атомарность переводов

Перед каждой попыткой перевода сохраняются:

- баланс отправителя;
- баланс получателя.

Если списание выполнено, но при зачислении возникает ошибка, оба баланса восстанавливаются.

Повторная попытка начинается с исходного состояния счетов и не может повторно списать ранее снятую сумму.

Откат выполняется как для логической ошибки, так и для непредвиденной технической ошибки.

Атомарность распространяется на балансы текущей учебной модели, работающей в памяти приложения.

## Повторные попытки

Логические ошибки не повторяются:

- замороженный счёт;
- закрытый счёт;
- недостаток средств;
- нарушение ограничений счёта;
- запрещённое время;
- некорректная операция.

Непредвиденные технические ошибки могут быть повторены в пределах установленного `max_retries`.

Перед каждой повторной попыткой состояние балансов полностью восстанавливается.

## Анализ рисков

Проверяются следующие признаки:

- крупная сумма;
- частые операции;
- новый получатель;
- ночная операция.

Высокий уровень риска блокирует транзакцию до изменения балансов.

Ночная операция блокируется независимо от полученного уровня риска.

Поэтому ночной перевод запрещён даже в том случае, если он имеет небольшую сумму, выполняется нечасто и направлен известному получателю.

## Аудит безопасности

В журнал аудита записываются:

- запросы на выполнение транзакций;
- результаты анализа риска;
- успешные транзакции;
- ошибки обработки;
- заблокированные операции.

Основные типы событий:

- `transaction_requested`;
- `risk_assessment`;
- `transaction_completed`;
- `transaction_failed`;
- `transaction_blocked`.

Критические блокировки сохраняются с уровнем `critical`.

Журнал хранится:

- в памяти приложения;
- в файле формата JSON Lines.

## Результат проверки безопасности

Если операция проходит все проверки, она передаётся на выполнение.

Если проверка не пройдена:

1. операция отклоняется;
2. балансы не изменяются;
3. причина сохраняется;
4. событие записывается в аудит;
5. подозрительное действие при необходимости сохраняется в банке.
