# Алгоритм асинхронного HTTP-клиента

## Назначение

Асинхронный HTTP-клиент загружает веб-страницы без блокировки потока выполнения и позволяет обрабатывать несколько URL конкурентно.

Основной компонент системы — класс `AsyncCrawler`.

## Инициализация клиента

При создании объекта `AsyncCrawler` принимается параметр:

```text
max_concurrent
```

Он определяет максимальное количество запросов, которые могут выполняться одновременно.

Значение должно быть положительным целым числом. Нулевые, отрицательные, дробные, строковые и логические значения отклоняются с исключением `ValueError`.

Во время инициализации создаются:

- ограничитель конкурентности `asyncio.Semaphore`;
- конфигурация таймаутов `aiohttp.ClientTimeout`;
- пустая ссылка на HTTP-сессию.

HTTP-сессия не создаётся в конструкторе, потому что её создание должно происходить внутри работающего цикла событий.

## Создание HTTP-сессии

Приватный метод `_get_session()` выполняет следующие действия:

1. Проверяет, существует ли текущая сессия.
2. Проверяет, не была ли сессия закрыта.
3. При необходимости создаёт `aiohttp.TCPConnector`.
4. Устанавливает лимит соединений, равный `max_concurrent`.
5. Создаёт `aiohttp.ClientSession`.
6. Передаёт сессии настройки таймаутов и пул соединений.
7. Возвращает готовую сессию.

Если открытая сессия уже существует, метод возвращает её повторно.

Повторное использование сессии позволяет использовать пул HTTP-соединений и не создавать новое соединение для каждого запроса.

## Таймауты

Для HTTP-сессии установлены два таймаута:

- подключение к серверу — 10 секунд;
- чтение данных — 30 секунд.

Таймаут подключения ограничивает время установления соединения.

Таймаут чтения ограничивает время ожидания очередной части ответа от сервера.

## Загрузка одного URL

Метод `fetch_url(url)` работает по следующему алгоритму:

1. Записывает в журнал начало загрузки URL.
2. Получает существующую HTTP-сессию или создаёт новую.
3. Ожидает разрешения от семафора.
4. Отправляет асинхронный GET-запрос.
5. Проверяет HTTP-статус ответа.
6. Читает тело ответа как текст.
7. Освобождает семафор.
8. Записывает в журнал успешное завершение.
9. Возвращает содержимое страницы.

Семафор освобождается автоматически после выхода из асинхронного контекстного менеджера.

## Обработка HTTP-ошибок

После получения ответа вызывается `raise_for_status()`.

Если сервер возвращает ошибочный HTTP-статус, например 404 или 500, создаётся `aiohttp.ClientResponseError`.

Краулер:

1. Перехватывает исключение.
2. Записывает URL и HTTP-статус в журнал.
3. Возвращает пустую строку.

## Обработка таймаутов

Если превышено время подключения или чтения ответа, возникает `asyncio.TimeoutError`.

Краулер:

1. Перехватывает таймаут.
2. Записывает URL и тип ошибки в журнал.
3. Возвращает пустую строку.

## Обработка сетевых ошибок

Остальные ошибки клиента перехватываются через `aiohttp.ClientError`.

К ним относятся:

- некорректный URL;
- невозможность установить соединение;
- ошибка DNS;
- разрыв соединения;
- другие ошибки HTTP-клиента.

После обработки ошибки метод возвращает пустую строку.

## Загрузка списка URL

Метод `fetch_urls(urls)` принимает список адресов и выполняет следующие действия:

1. Для каждого URL создаёт вызов `fetch_url()`.
2. Передаёт все вызовы в `asyncio.gather()`.
3. Запускает загрузки конкурентно.
4. Ожидает завершения всех загрузок.
5. Объединяет URL и полученные ответы в словарь.
6. Возвращает словарь формата `URL → содержимое`.

Пример результата:

```python
{
    "https://example.com": "<html>...</html>",
    "https://example.com/missing": "",
}
```

Пустая строка означает, что запрос завершился обработанной ошибкой.

## Ограничение конкурентности

Количество одновременно активных запросов ограничивается двумя механизмами:

- `asyncio.Semaphore`;
- лимитом `aiohttp.TCPConnector`.

Семафор ограничивает количество одновременно выполняющихся участков загрузки.

Коннектор ограничивает количество сетевых соединений и управляет их повторным использованием.

Если количество URL превышает установленный лимит, остальные запросы ожидают освобождения семафора.

## Последовательная загрузка

При последовательной загрузке каждый следующий запрос начинается только после завершения предыдущего:

1. Запускается первый запрос.
2. Выполнение ожидает его завершения.
3. Запускается второй запрос.
4. Процесс повторяется для всех URL.

Общее время приблизительно равно сумме времени всех запросов.

## Параллельная загрузка

При параллельной загрузке несколько запросов ожидают ответы одновременно:

1. Создаются вызовы загрузки всех URL.
2. `asyncio.gather()` запускает их конкурентно.
3. Семафор пропускает разрешённое количество запросов.
4. Пока один запрос ожидает сеть, цикл событий выполняет другие запросы.
5. После завершения всех запросов формируется результат.

Общее время приближается ко времени самой медленной группы запросов, а не к сумме времени каждого запроса.

## Закрытие клиента

Метод `close()` проверяет состояние HTTP-сессии.

Если сессия существует и ещё открыта, она закрывается асинхронно.

Повторный вызов `close()` не вызывает ошибку.

После закрытия `_get_session()` может создать новую сессию при следующем запросе.

Закрытие сессии освобождает:

- TCP-соединения;
- пул соединений;
- сетевые ресурсы клиента.

## Логирование

Для каждого запроса журналируется:

- начало загрузки;
- успешное завершение;
- HTTP-ошибка;
- таймаут;
- сетевая ошибка.

Сообщения содержат URL, а для HTTP-ошибок также указывается код ответа.

## Тестирование

Для тестирования используется локальный HTTP-сервер на базе `aiohttp.web`.

Локальный сервер предоставляет обработчики:

- успешного ответа;
- ответа с HTTP 404;
- ответа с искусственной задержкой.

Такой подход позволяет тестировать сетевое поведение без зависимости от внешнего интернета.

Тесты проверяют:

- параметры конструктора;
- валидацию ограничения конкурентности;
- настройки таймаутов;
- настройки пула соединений;
- повторное использование сессии;
- закрытие и повторное создание сессии;
- успешную загрузку;
- HTTP-ошибки;
- таймауты;
- сетевые ошибки;
- конкурентную загрузку списка URL;
- работу с пустым списком;
- сравнение последовательного и параллельного выполнения.

## Ограничения текущей реализации

На текущем этапе клиент:

- загружает ответ полностью в память;
- возвращает только текст страницы;
- обозначает обработанную ошибку пустой строкой;
- не выполняет повторные попытки;
- не ограничивает частоту запросов по времени;
- не обрабатывает `robots.txt`;
- не сохраняет результаты в файлы или базу данных;
- не выполняет разбор HTML.

Эти возможности будут добавляться на следующих этапах проекта.
