# Анализ рисков

## Назначение

`RiskAnalyzer` анализирует транзакции до их передачи в `TransactionProcessor`.

Результат анализа содержит:

- уровень риска;
- список обнаруженных причин;
- сумму операции;
- валюту;
- номер счёта получателя.

## Признаки риска

### Крупная сумма

Если сумма транзакции достигает установленного порога крупной операции, добавляется причина:

`large_amount`

### Частые операции

Анализатор хранит историю операций клиента в памяти приложения.

Если количество операций клиента за установленный временной интервал достигает допустимого предела, добавляется причина:

`frequent_operations`

### Новый получатель

Если клиент ранее не переводил средства на указанный счёт, добавляется причина:

`new_recipient`

### Ночная операция

Если транзакция создаётся с `00:00` включительно до `05:00` исключительно, добавляется причина:

`night_operation`

## Определение уровня риска

Уровень риска зависит от количества обнаруженных признаков:

- нет признаков — `RiskLevel.LOW`;
- один признак — `RiskLevel.MEDIUM`;
- два и более признака — `RiskLevel.HIGH`.

## Блокировка высокого риска

Метод `Bank.process_transaction()` выполняет анализ до передачи транзакции процессору.

Если получен уровень `RiskLevel.HIGH`:

1. `TransactionProcessor` не вызывается;
2. балансы счетов не изменяются;
3. количество попыток транзакции остаётся равным нулю;
4. транзакция получает статус `failed`;
5. в `failure_reason` сохраняется причина блокировки;
6. в аудит записывается событие `transaction_blocked` уровня `critical`;
7. метод возвращает `False`.

## Безусловная блокировка ночных переводов

Ночная операция является одновременно:

- признаком риска для отчётности;
- самостоятельным основанием для запрета перевода.

После анализа риска `Bank` отдельно проверяет текущее время.

Если операция выполняется с `00:00` включительно до `05:00` исключительно:

1. транзакция блокируется независимо от рассчитанного уровня риска;
2. `TransactionProcessor` не вызывается;
3. балансы счетов не изменяются;
4. количество попыток остаётся равным нулю;
5. транзакция получает статус `failed`;
6. в `failure_reason` сохраняется запрет ночных переводов;
7. действие сохраняется в `suspicious_actions`;
8. в аудит записывается событие `transaction_blocked`;
9. метод возвращает `False`.

Поэтому небольшой ночной перевод на уже известный счёт также не может быть выполнен.

Дополнительная проверка времени выполняется внутри `TransactionProcessor`. Она защищает систему при прямом использовании процессора без класса `Bank`.

## Регистрация результата

После успешной обработки информация о транзакции добавляется в историю анализатора.

История используется при последующих проверках:

- частоты операций;
- новых получателей;
- риск-профиля клиента.

Неуспешные и заблокированные транзакции учитываются в аудите и отчётах в соответствии с их результатом.

## Взаимодействие с аудитом

Результат анализа сохраняется как событие:

`risk_assessment`

Для низкого риска используется информационный уровень аудита.

Для среднего и высокого риска используются более важные уровни аудита.

Заблокированная операция дополнительно создаёт событие:

`transaction_blocked`

Запись содержит сведения о транзакции, клиенте, уровне риска и причинах блокировки.

## Отчёты

Результаты анализа используются для формирования:

- списка подозрительных транзакций;
- риск-профиля клиента;
- статистики заблокированных операций;
- статистики ошибок.

## Ограничения модели

Анализ выполняется на данных, находящихся в памяти приложения.

Внешние API, реальные банковские правила, котировки и база данных не используются.
