# Модель транзакции

## Назначение

Класс `Transaction` представляет перевод денежных средств между двумя банковскими счетами.

Транзакция хранит данные операции и её текущее состояние, но самостоятельно не изменяет балансы счетов. Выполнение перевода относится к ответственности `TransactionProcessor`.

## Данные транзакции

Транзакция содержит:

- уникальный идентификатор;
- тип операции;
- сумму;
- валюту;
- рассчитанную комиссию;
- счёт отправителя;
- счёт получателя;
- статус;
- причину отказа или отмены;
- время создания;
- запланированное время выполнения;
- время завершения;
- количество попыток обработки.

## Типы транзакций

Поддерживаются два типа:

- `internal_transfer` — внутренний перевод;
- `external_transfer` — внешний перевод с комиссией.

## Статусы транзакций

Транзакция может находиться в одном из состояний:

- `pending` — ожидает обработки;
- `processing` — обрабатывается;
- `completed` — успешно завершена;
- `failed` — завершена с ошибкой;
- `cancelled` — отменена до обработки.

Новая транзакция получает статус `pending`.

Перед выполнением процессор устанавливает статус `processing`.

После успешного перевода устанавливается статус `completed`.

При логической или технической ошибке устанавливается статус `failed`.

При отмене ожидающей операции устанавливается статус `cancelled`.

## Создание транзакции

При создании выполняются следующие действия:

1. Проверяется или автоматически создаётся идентификатор.
2. Проверяется тип транзакции.
3. Сумма преобразуется в `Decimal`.
4. Проверяется конечность и положительность суммы.
5. Проверяется валюта.
6. Проверяются счета отправителя и получателя.
7. Проверяется, что номера счетов различаются.
8. Устанавливается нулевая комиссия.
9. Устанавливается статус `pending`.
10. Записывается время создания.
11. Устанавливается запланированное время.
12. Счётчик попыток устанавливается в ноль.

Если идентификатор не передан, используется первые восемь символов UUID.

## Время выполнения

Транзакция хранит три временные отметки:

- `created_at` — момент создания;
- `scheduled_at` — время, после которого разрешена обработка;
- `processed_at` — момент завершения, отказа или отмены.

Запланированное время не может быть раньше времени создания.

Если `scheduled_at` не передан, транзакция может обрабатываться сразу.

## Причина завершения

Для успешной транзакции `failure_reason` имеет значение `None`.

При ошибке поле содержит текст причины отказа.

При отмене поле содержит причину отмены.

## Количество попыток

Поле `attempts` увеличивается перед каждой попыткой выполнения операции.

Логические ошибки завершают транзакцию после первой попытки.

Техническая ошибка может привести к повторной попытке.
