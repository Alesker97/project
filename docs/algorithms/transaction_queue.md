# Очередь транзакций

## Назначение

Класс `TransactionQueue` управляет порядком обработки транзакций.

Очередь поддерживает:

- добавление транзакций;
- приоритеты;
- сохранение порядка добавления;
- отложенные операции;
- отмену ожидающих транзакций.

## Добавление транзакции

Метод `add()` выполняет следующие действия:

1. Проверяет тип переданного объекта.
2. Проверяет приоритет.
3. Проверяет, что транзакция имеет статус `pending`.
4. Проверяет, что идентификатор ещё не добавлялся.
5. Сохраняет транзакцию, её приоритет и порядковый номер.
6. Увеличивает внутренний порядковый номер.

Повторное добавление транзакции с тем же идентификатором запрещено.

## Приоритеты

Поддерживаются три уровня:

- `LOW`;
- `NORMAL`;
- `HIGH`.

Чем больше числовое значение приоритета, тем раньше транзакция будет выбрана для обработки.

## Выбор следующей транзакции

Метод `get_next()` работает следующим образом:

1. Получает текущее время.
2. Выбирает транзакции, у которых наступило `scheduled_at`.
3. Исключает отложенные транзакции, время которых ещё не наступило.
4. Среди доступных операций выбирает наибольший приоритет.
5. При одинаковом приоритете выбирает транзакцию, добавленную раньше.
6. Удаляет выбранную транзакцию из очереди.
7. Возвращает её процессору.

Если доступных операций нет, возвращается `None`.

## Отложенные операции

Отложенная транзакция хранится в очереди, но не возвращается для обработки раньше установленного времени.

Высокий приоритет не позволяет выполнить транзакцию раньше `scheduled_at`.

После наступления установленного времени транзакция участвует в обычном выборе по приоритету.

## Отмена транзакции

Метод `cancel()` получает идентификатор транзакции и причину отмены.

При отмене:

1. Выполняется поиск транзакции в очереди.
2. Транзакция удаляется из очереди.
3. Её статус изменяется на `cancelled`.
4. Причина записывается в `failure_reason`.
5. В `processed_at` записывается время отмены.

Отменить можно только транзакцию, которая ещё находится в очереди.

## Управление временем

Очередь получает время через `time_provider`.

По умолчанию используется текущее системное время.

В тестах и демонстрации используется управляемый источник времени. Это позволяет проверять отложенные операции без ожидания в реальном времени.
