# Демонстрационная программа

## Назначение

Демонстрационная программа объединяет все реализованные компоненты банковской системы в единый воспроизводимый сценарий.

Программа показывает:

- создание банка;
- регистрацию клиентов;
- открытие счетов;
- создание транзакций;
- работу очереди;
- обработку приоритетов;
- отложенные операции;
- отмену транзакций;
- успешные переводы;
- ошибки обработки;
- анализ рисков;
- блокировку подозрительных операций;
- ночные ограничения;
- аудит;
- счета и историю клиента;
- итоговые банковские отчёты.

## Структура демонстрационного слоя

Демонстрационная программа разделена на четыре модуля:

- `demo_builder.py` — создание исходных объектов;
- `demo_scenarios.py` — подготовка очереди и выполнение сценариев;
- `demo_report.py` — расчёт и вывод отчётов;
- `demo_runner.py` — координация полной демонстрации.

Файл `main.py` является только точкой запуска программы.

## Инициализация

При запуске создаются:

- один банк;
- шесть клиентов;
- двенадцать счетов;
- сорок транзакций;
- очередь транзакций;
- обработчик транзакций;
- анализатор рисков;
- журнал аудита;
- генератор аудиторских отчётов;
- управляемый источник времени.

Все идентификаторы, суммы и timestamps заданы явно. Благодаря этому результат демонстрации воспроизводится одинаково при каждом запуске.

## Счета

Всего создаётся двенадцать счетов.

В демонстрации используются:

- обычные банковские счета;
- накопительные счета;
- премиальные счета;
- инвестиционные счета.

Поддерживаются счета в:

- RUB;
- USD;
- EUR.

Остальные поддерживаемые валюты также присутствуют в итоговом банковском отчёте с нулевым балансом.

## Управляемое время

Для воспроизводимости используется `MutableClock`.

Начальное время:

`2026-09-29 12:00:00`

Время отложенных операций:

`2026-09-29 14:00:00`

Время ночной операции:

`2026-09-30 02:00:00`

Все компоненты получают время из одного источника:

- `Bank`;
- `AuditLog`;
- `RiskAnalyzer`;
- `TransactionQueue`;
- `TransactionProcessor`.

Создаётся сорок транзакций.

Они заранее распределены по сценариям:

До выполнения все транзакции имеют статус `pending`.

## Приоритеты

Для транзакций используются три уровня приоритета:

- `high`;
- `normal`;
- `low`.

Распределение:

| Приоритет | Количество |
|---|---:|
| Высокий | 7 |
| Обычный | 17 |
| Низкий | 16 |

Очередь сначала возвращает доступные транзакции с высоким приоритетом.

Если несколько транзакций имеют одинаковый приоритет, сохраняется порядок их добавления.

## Отложенные операции

Транзакции `demo-tx-021` и `demo-tx-022` запланированы на `14:00`.

Транзакция `demo-tx-036` запланирована на `02:00` следующего дня.

До наступления заданного времени такие транзакции остаются в очереди.

После изменения времени через `MutableClock` они становятся доступными для обработки.

## Отмена транзакций

До начала обработки отменяются:

- `demo-tx-037`;
- `demo-tx-038`;
- `demo-tx-039`;
- `demo-tx-040`.

Каждая из них получает:

- статус `cancelled`;
- причину отмены;
- время завершения;
- нулевое количество попыток.

Отменённые транзакции не передаются банку и процессору.

## Успешные операции

Двадцать четыре транзакции выполняются успешно.

Они демонстрируют:

- внутренние переводы;
- внешние переводы;
- процентные комиссии;
- фиксированные комиссии премиальных счетов;
- операции разных клиентов;
- операции с разными приоритетами;
- отложенное выполнение.

Успешная транзакция получает:

- статус `completed`;
- одну попытку выполнения;
- время завершения;
- рассчитанную комиссию.

## Ошибочные операции

Пять транзакций доходят до `TransactionProcessor`, но завершаются ошибкой.

Проверяются следующие ситуации:

1. недостаточно средств;
2. заморожен счёт отправителя;
3. отсутствует курс валютной конвертации;
4. нарушен минимальный остаток накопительного счёта;
5. заморожен счёт получателя.

Каждая такая транзакция получает:

- статус `failed`;
- одну попытку;
- причину отказа.

После демонстрации временно замороженные счета возвращаются в статус `active`.

## Подозрительные операции

Шесть дневных транзакций блокируются из-за высокого уровня риска.

Используются признаки:

- `large_amount`;
- `frequent_operations`;
- `new_recipient`.

Такие операции блокируются классом `Bank` до передачи в `TransactionProcessor`.

Поэтому они имеют:

- статус `failed`;
- нулевое количество попыток;
- причину блокировки;
- неизменённые балансы счетов.

## Ночная операция

Транзакция `demo-tx-036` становится доступной в `02:00`.

Она получает признак:

`night_operation`

Ночной перевод блокируется независимо от рассчитанного уровня риска.

Причина отказа:

`Переводы запрещены с 00:00 до 05:00.`

Попытка сохраняется:

- в аудите;
- в списке подозрительных действий банка.

## Атомарность

Каждая попытка перевода выполняется атомарно.

Перед изменением счетов сохраняются:

- баланс отправителя;
- баланс получателя.

Если после списания возникает ошибка, оба баланса восстанавливаются до состояния перед попыткой.

Повторная попытка не может привести к повторному списанию одной суммы.

## Журнал очереди

Для очереди формируется отдельный демонстрационный журнал.

Он содержит события:

- `transaction_queued`;
- `transaction_cancelled`.

Для добавленной транзакции показываются:

- идентификатор;
- приоритет;
- запланированное время.

Для отменённой транзакции показываются:

- идентификатор;
- статус;
- причина отмены.

## Журнал обработки

Для каждой обработанной транзакции фиксируются:

- идентификатор;
- результат;
- итоговый статус;
- количество попыток;
- причина отказа.

Возможные результаты:

- `transaction_completed`;
- `transaction_failed`;
- `transaction_blocked`.

## Счета клиента

Демонстрационная программа показывает два счёта Алексея Иванова.

Для каждого счёта выводятся:

- тип;

- валюта;

## История клиента

История клиента строится по общему списку транзакций.

В неё попадают операции, где счёт клиента является:

- отправителем;
- получателем.

Для каждой операции показываются:

- идентификатор;
- направление;
- сумма;
- валюта;
- статус;
- причина отказа.

В историю входят:

- успешные;
- ошибочные;
- заблокированные;
- отменённые операции.

## Подозрительные операции

Отчёт аудита показывает операции со средним и высоким уровнем риска.

Для каждой операции выводятся:

- идентификатор транзакции;
- идентификатор клиента;
- уровень риска;
- обнаруженные причины.

## Риск-профиль клиента

Для выбранного клиента рассчитываются:

- общее количество проанализированных операций;
- количество операций каждого уровня риска;
- количество заблокированных операций;
- максимальный обнаруженный уровень риска.
