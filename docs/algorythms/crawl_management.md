# Управление обходом, очередями и конкурентностью

## Назначение

Система управления обходом отвечает за:

- хранение URL в очереди;
- приоритетную обработку URL;
- ограничение глобальной конкурентности;
- ограничение запросов к одному домену;
- автоматическое обнаружение новых страниц;
- контроль глубины обхода;
- фильтрацию URL;
- исключение дубликатов;
- хранение успешных и неудачных результатов;
- отображение прогресса.

Основные компоненты:

```text
src/queues/crawler_queue.py
src/concurrency/semaphore_manager.py
src/crawler/async_crawler.py
```

## CrawlerQueue

Класс `CrawlerQueue` управляет URL, ожидающими обработки.

Основные методы:

```python
add_url(url, priority=0)
await get_next()
mark_processed(url)
mark_failed(url, error)
get_stats()
```

## Приоритетная очередь

Внутри используется:

```python
asyncio.PriorityQueue
```

Элемент очереди представлен кортежем:

```python
(
    -priority,
    sequence,
    url,
)
```

Отрицательное значение позволяет обрабатывать больший пользовательский приоритет раньше меньшего.

Например:

```text
priority=10 → внутренний приоритет -10
priority=5  → внутренний приоритет -5
priority=0  → внутренний приоритет 0
```

Поле `sequence` сохраняет порядок добавления URL с одинаковым приоритетом.

## Состояния URL в очереди

Очередь хранит:

- URL, ожидающие обработки;
- активные URL;
- успешно обработанные URL;
- URL, завершившиеся ошибкой;
- все URL, которые когда-либо добавлялись.

Множество известных URL не позволяет добавить один адрес повторно.

После вызова `get_next()` URL переходит из ожидающего состояния в активное.

После обработки вызывается один из методов:

```python
mark_processed(url)
mark_failed(url, error)
```

## Статистика очереди

Метод `get_stats()` возвращает:

```python
{
    "queued": 10,
    "active": 2,
    "processed": 20,
    "failed": 1,
    "total": 33,
}
```

Где:

- `queued` — ожидающие URL;
- `active` — URL в обработке;
- `processed` — успешно обработанные URL;
- `failed` — URL с ошибками;
- `total` — общее количество принятых очередью URL.

## SemaphoreManager

Класс `SemaphoreManager` управляет конкурентным выполнением запросов.

Используются два уровня ограничений:

1. Глобальный лимит.
2. Лимит для одного домена.

Пример:

```python
manager = SemaphoreManager(
    global_limit=10,
    per_domain_limit=2,
)
```

Это означает:

- одновременно выполняется не более десяти запросов;
- к одному домену одновременно выполняется не более двух запросов.

## Доменный семафор

Для каждого домена семафор создаётся при первом обращении.

Например:

```text
example.com → отдельный семафор
python.org  → отдельный семафор
```

Адреса одного домена используют общий доменный лимит:

```text
https://example.com/page-1
https://example.com/page-2
https://example.com/page-3
```

Разные домены могут обрабатываться конкурентно, пока не достигнут глобальный лимит.

## Использование SemaphoreManager

Менеджер используется как асинхронный контекстный менеджер:

```python
async with manager.limit(url):
    ...
```

Алгоритм:

1. Из URL извлекается домен.
2. Получается семафор домена.
3. Ожидается разрешение доменного семафора.
4. Ожидается разрешение глобального семафора.
5. Увеличивается количество активных задач.
6. Выполняется сетевой запрос.
7. Уменьшается количество активных задач.
8. Освобождается глобальный семафор.
9. Освобождается доменный семафор.

Освобождение выполняется и при успешном результате, и при исключении.

## Статистика конкурентности

`SemaphoreManager.get_stats()` возвращает:

```python
{
    "active": 2,
    "peak_active": 5,
    "active_by_domain": {
        "example.com": 2,
    },
    "peak_by_domain": {
        "example.com": 2,
        "python.org": 1,
    },
}
```

Статистика показывает текущее и максимальное количество активных задач.

## Состояние AsyncCrawler

Класс `AsyncCrawler` хранит:

```python
visited_urls
failed_urls
processed_urls
```

### visited_urls

Множество URL, переданных в обработку:

```python
set[str]
```

Один URL не может быть обработан повторно в рамках одного запуска `crawl()`.

### failed_urls

Словарь URL и причин ошибок:

```python
{
    "https://example.com/missing": "HTTP 404",
}
```

### processed_urls

Словарь успешно обработанных страниц:

```python
{
    "https://example.com": {
        "url": "https://example.com",
        "title": "Example Domain",
        "text": "...",
        "links": [],
    }
}
```

При каждом новом вызове `crawl()` состояние предыдущего запуска сбрасывается.

## Метод crawl

Основной метод обхода:

```python
async def crawl(
    self,
    start_urls: list[str],
    max_pages: int = 100,
    same_domain_only: bool = False,
    exclude_patterns: list[str] | None = None,
    include_patterns: list[str] | None = None,
) -> dict[str, dict[str, object]]
```

Метод возвращает успешно обработанные страницы.

## Алгоритм обхода

1. Проверяются входные параметры.
2. Стартовые URL нормализуются.
3. Из URL удаляются фрагменты.
4. Сбрасывается состояние предыдущего обхода.
5. Определяются разрешённые домены.
6. Стартовые URL добавляются в очередь.
7. Из очереди выбирается группа URL.
8. Группа обрабатывается конкурентно.
9. Страницы загружаются и разбираются.
10. Ошибки записываются в `failed_urls`.
11. Успешные результаты записываются в `processed_urls`.
12. Найденные ссылки проходят фильтрацию.
13. Разрешённые ссылки добавляются в очередь.
14. Процесс повторяется до достижения `max_pages` или опустошения очереди.

## Ограничение количества страниц

Параметр:

```python
max_pages
```

ограничивает количество URL, переданных в обработку.

В это количество входят:

- успешно обработанные страницы;
- страницы, завершившиеся ошибкой.

Если лимит достигнут, обход завершается. URL, уже обнаруженные, но не обработанные, могут остаться в очереди.

Например:

```text
Обработано: 10
В очереди: 57
```

Это означает, что обход корректно остановился после десяти страниц.

## Контроль глубины

Максимальная глубина задаётся в конструкторе:

```python
crawler = AsyncCrawler(max_depth=2)
```

Стартовая страница имеет глубину:

```text
0
```

Ссылки со стартовой страницы:

```text
1
```

Ссылки со страниц глубины `1`:

```text
2
```

Новая ссылка добавляется только при условии:

```python
next_depth <= max_depth
```

При `max_depth=0` обрабатываются только стартовые URL.

## Защита от дубликатов

Дубликаты исключаются двумя компонентами:

- `CrawlerQueue` хранит все известные URL;
- `AsyncCrawler` хранит `visited_urls` и глубины обнаруженных URL.

Если ссылка встречается на нескольких страницах, она добавляется и обрабатывается только один раз.

URL с разными query-параметрами считаются разными:

```text
/page?id=1
/page?id=2
```

Фрагменты удаляются:

```text
/page#first
/page#second
```

Оба адреса преобразуются в:

```text
/page
```

## Фильтр домена

При использовании:

```python
same_domain_only=True
```

краулер принимает только URL доменов стартовых страниц.

Если передано несколько стартовых URL, разрешаются домены всех этих URL.

Сравнение выполняется по `hostname`.

## Исключающие паттерны

Параметр:

```python
exclude_patterns
```

отклоняет URL, содержащие один из указанных фрагментов:

```python
exclude_patterns=[
    "/login",
    "/logout",
    ".pdf",
]
```

Паттерны являются обычными подстроками.

## Включающие паттерны

Если передан `include_patterns`, новая ссылка добавляется только при совпадении хотя бы с одним фрагментом:

```python
include_patterns=[
    "/articles/",
    "/news/",
]
```

Стартовые URL обрабатываются независимо от включающих паттернов.

Сначала применяется доменный фильтр, затем включающие и исключающие паттерны.

## Порядок обхода

Стартовые URL имеют приоритет `0`.

Найденные ссылки получают приоритет, зависящий от глубины:

```python
priority = -depth
```

Так как большее значение приоритета обрабатывается раньше, страницы меньшей глубины получают преимущество.

Это создаёт поведение, близкое к обходу в ширину:

```text
depth 0 → depth 1 → depth 2
```

## Обработка ошибок

`fetch_url()` сохраняет причины обработанных ошибок:

- `HTTP 404`;
- `HTTP 500`;
- превышение времени ожидания;
- сетевые ошибки;
- некорректные URL.

Если при обработке возникает непредвиденное исключение, оно также сохраняется в `failed_urls`, а работа остальных задач продолжается.

## Прогресс

После завершения каждой страницы выводится:

```text
Обработано: 10 | В очереди: 57 | Ошибок: 0 | Скорость: 3.63 стр/сек
```

Скорость рассчитывается как:

```text
количество завершённых страниц / прошедшее время
```

Завершёнными считаются успешные и неудачные попытки.

## Сохранение результатов

Демонстрационная программа сохраняет результат в:

```text
output/crawl_results.json
```

Каталог создаётся автоматически.

Запись выполняется асинхронно через `aiofiles`.

JSON сохраняется:

- с отступами;
- в кодировке UTF-8;
- без преобразования кириллицы в escape-последовательности.

Каталог `output/` добавлен в `.gitignore`, потому что содержит генерируемые результаты.

## Тестирование

Тесты очереди проверяют:

- приоритеты;
- FIFO;
- дубликаты;
- успешные состояния;
- неудачные состояния;
- статистику.

Тесты семафоров проверяют:

- глобальный лимит;
- доменный лимит;
- разные домены;
- активные задачи;
- освобождение семафоров при исключении.

Тесты обхода проверяют:

- глубину;
- максимальное количество страниц;
- доменный фильтр;
- включающие паттерны;
- исключающие паттерны;
- HTTP-ошибки;
- отсутствие дубликатов;
- сброс состояния;
- прогресс;
- статистику.

Все сетевые тесты выполняются на локальном сервере `aiohttp.web`.
