# Ограничение скорости и правила вежливости

## Компоненты

- `src/concurrency/rate_limiter.py` — интервалы между началами запросов.
- `src/parsers/robots_parser.py` — загрузка, разбор и кэширование `robots.txt`.
- `src/crawler/async_crawler.py` — применение правил, повторы и статистика.
- `src/main.py` — демонстрация на внешних сайтах и локальном учебном сайте.

Сетевые операции выполняются через `aiohttp`, ожидания — через `asyncio.sleep()`.
Загрузка страниц и `robots.txt` внутри краулера использует одну HTTP-сессию и её пул соединений.

## Настройка краулера

```python
crawler = AsyncCrawler(
    max_concurrent=5,
    max_concurrent_per_domain=2,
    requests_per_second=2.0,
    per_domain=True,
    respect_robots=True,
    min_delay=0.5,
    jitter=0.1,
    user_agent="MyBot/1.0",
    max_retries=2,
    backoff_factor=0.5,
    max_backoff=30.0,
)

try:
    results = await crawler.crawl(
        ["https://example.com"],
        max_pages=10,
        same_domain_only=True,
    )
    print(crawler.get_request_stats())
finally:
    await crawler.close()
```

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `requests_per_second` | `1.0` | Максимальная частота начала запросов |
| `per_domain` | `True` | Отдельные интервалы для каждого hostname |
| `respect_robots` | `True` | Проверка правил перед запросом страницы |
| `min_delay` | `0.0` | Минимальный интервал в секундах |
| `jitter` | `0.0` | Максимальная добавочная случайная задержка |
| `user_agent` | `"AsyncCrawler/1.0"` | HTTP-заголовок и имя для проверки правил |
| `max_retries` | `2` | Число повторов после первой попытки |
| `backoff_factor` | `0.5` | Пауза перед первым повтором |
| `max_backoff` | `30.0` | Верхняя граница экспоненциальной паузы |

Частота должна быть конечным положительным числом. Задержки должны быть конечными неотрицательными числами. Ротация User-Agent не реализована: один экземпляр использует одно настроенное имя.

## RateLimiter

Основной интерфейс:

```python
limiter = RateLimiter(requests_per_second=2.0, per_domain=True)
await limiter.acquire("example.com")
```

Для каждого домена хранятся `asyncio.Lock` и время последнего разрешения. Имена доменов приводятся к нижнему регистру. Разные порты и схемы одного hostname используют общий скоростной лимит.

При `per_domain=False` все домены используют один замок и один таймер. Вызовы без аргумента `domain` также используют общий ключ.

Алгоритм `acquire()`:

1. Выбирает доменный или глобальный ключ.
2. Захватывает соответствующий замок.
3. Определяет интервал до следующего разрешения.
4. Асинхронно ожидает остаток интервала.
5. Записывает фактическое время выдачи разрешения и обновляет статистику.
6. Освобождает замок, в том числе при отмене задачи.

Интервал вычисляется так:

```text
max(1 / requests_per_second, min_delay, Crawl-delay) + uniform(0, jitter)
```

Первый запрос выполняется сразу. После простоя разрешения не накапливаются: серия одновременных запросов по-прежнему разделяется интервалами. Используется монотонное время, которое не зависит от изменения системных часов.

Семафоры ограничивают количество одновременных запросов, а RateLimiter — частоту их начала. Краулер сначала получает семафоры, затем разрешение RateLimiter непосредственно перед HTTP-запросом. Ожидающий разрешение запрос занимает слот конкурентности.

## RobotsParser

Основной интерфейс:

```python
parser = RobotsParser(user_agent="MyBot/1.0")
try:
    info = await parser.fetch_robots("https://example.com/articles/")
    allowed = parser.can_fetch("https://example.com/private", "MyBot/1.0")
    delay = parser.get_crawl_delay("MyBot/1.0")
finally:
    await parser.close()
```

`fetch_robots()` возвращает словарь с адресом `robots.txt`, HTTP-статусом, задержкой для настроенного агента и флагом полного запрета обхода.

Правила загружаются с корневого `/robots.txt`, независимо от пути исходного URL. Кэш разделяется по origin: схема, hostname и порт. Стандартные порты нормализуются, поэтому `https://example.com` и `https://example.com:443` используют одну запись.

Для каждого origin есть отдельный замок. Несколько конкурентных запросов к ещё неизвестному сайту вызывают одну загрузку `robots.txt`. Кэш действует всё время жизни парсера, включая повторные вызовы `crawl()`; автоматического обновления по TTL на этом этапе нет.

Правила `Allow`, `Disallow` и выбор User-Agent обрабатывает стандартный `urllib.robotparser.RobotFileParser`. Для загрузки используется асинхронный HTTP-клиент; синхронный `RobotFileParser.read()` не вызывается. Поддержка правил пути соответствует стандартному парсеру Python, без добавления расширений `*` и `$`.

`Crawl-delay` разбирается отдельно для поддержки дробных секунд. Учитываются группы User-Agent, пустые строки и комментарии. Некорректные и отрицательные задержки игнорируются. Если подходящей задержки нет, возвращается `0.0`.

При работе с несколькими сайтами задержку нужно получать с явным URL:

```python
delay = parser.get_crawl_delay("MyBot/1.0", url="https://example.com/page")
```

Без `url` метод использует последний загруженный origin. Краулер всегда передаёт URL явно, чтобы конкурентная загрузка другого сайта не подменила задержку.

## Ошибки загрузки robots.txt

| Ситуация | Поведение |
| --- | --- |
| Успешный ответ | Разобрать и кэшировать правила |
| `404` и прочие `4xx`, кроме перечисленных ниже | Разрешить обход без правил |
| `401`, `403`, `429` | Запретить обход |
| `5xx`, ошибка соединения или таймаут | Запретить обход |
| Непригодный редирект или превышение лимита переходов | Запретить обход |

В составе краулера временные ошибки сначала проходят настроенные повторные попытки. После их исчерпания результат запрета сохраняется в кэше. Самостоятельный `RobotsParser` выполняет загрузку без системы повторов краулера.

Поддерживается до пяти переходов при загрузке `robots.txt`. Полученные правила относятся к исходному origin, даже если файл был перенаправлен на другой адрес.

## Последовательность запроса

1. Проверить формат URL.
2. Загрузить или получить из кэша `robots.txt`.
3. Проверить разрешение для настроенного User-Agent.
4. При запрете записать URL в `blocked_urls` и причину в `failed_urls`, вывести предупреждение и завершить обработку без запроса страницы.
5. Получить `Crawl-delay` именно для этого URL.
6. Получить разрешения доменного и глобального семафоров.
7. Дождаться разрешения RateLimiter.
8. Выполнить запрос с настроенным HTTP-заголовком User-Agent.
9. Освободить соединение и семафоры.
10. При временной ошибке дождаться backoff и повторить попытку.

`robots.txt` также загружается через семафоры, RateLimiter и backoff. Для него не выполняется рекурсивная проверка самого себя.

Автоматические редиректы `aiohttp` отключены. Каждый адрес перенаправления страницы заново проходит проверку `robots.txt` и задержки. Поддерживается до десяти переходов; цикл перенаправлений завершается ошибкой.

При `respect_robots=False` загрузка и проверка правил пропускаются. Ограничение скорости, `min_delay`, jitter и backoff продолжают работать.

## Экспоненциальный backoff

Повторяются:

- HTTP `429` и `5xx`;
- ошибки соединения;
- ошибки чтения тела ответа;
- таймауты.

Остальные HTTP-ошибки, например `404`, не повторяются. Отмена асинхронной задачи передаётся вызывающему коду.

Пауза перед повтором с номером `n`, начиная с нуля:

```text
min(backoff_factor * 2**n, max_backoff)
```

При настройках по умолчанию выполняется не более трёх попыток: первая, затем повторы с паузами `0.5` и `1.0` секунды. Ожидание backoff не удерживает соединение или семафоры. RateLimiter проверяется и для повторов, поэтому фактический интервал может быть больше backoff.

## Статистика

`get_request_stats()` возвращает:

| Поле | Значение |
| --- | --- |
| `requests` | Количество начатых HTTP-попыток, включая robots.txt, повторы и редиректы |
| `requests_per_second` | Число начал запросов за последнюю скользящую секунду |
| `average_delay` | Средний фактический интервал между разрешениями одного ключа RateLimiter |
| `blocked` | Количество уникальных входных URL, заблокированных правилами |
| `retries` | Количество назначенных повторов |

При доменных лимитах средняя задержка объединяет интервалы внутри каждого домена; одновременные запросы к разным доменам не создают нулевые интервалы. Начало самого первого запроса не образует интервал.

Эти поля также включены в `get_crawl_stats()`. Скорость `speed` продолжает измеряться в завершённых страницах в секунду; это отдельный показатель от частоты HTTP-попыток.

Заблокированные страницы входят в `failed` и дополнительно учитываются в `blocked`: складывать эти два значения нельзя. Для редиректа блокировка записывается на исходный URL, а запрещённый адрес присутствует в сообщении об ошибке.

Перед новым `crawl()` счётчики сбрасываются. Кэш robots.txt и время последних разрешений сохраняются, чтобы новый обход не обходил ограничения скорости.

## Демонстрация через main

```bash
python -m src.main
```

Программа демонстрирует последовательную и конкурентную загрузку внешних страниц, парсинг и обход `quotes.toscrape.com`. Результаты обхода записываются в `output/crawl_results.json`.

Затем `demonstrate_politeness()` поднимает локальный сервер на `127.0.0.1` со свободным портом:

- `/robots.txt` запрещает `/private` для `MyBot` и задаёт `Crawl-delay: 0.15`;
- `/` ссылается на открытую, запрещённую и временно недоступную страницы;
- `/unstable` дважды возвращает `503`, затем успешно отвечает;
- сервер считает фактические обращения к `/private`.

Ожидаемый результат локальной части:

```text
Успешных страниц: 3
HTTP-запросов (включая robots.txt и повторы): 6
Заблокировано URL: 1; повторов: 2
Запросов к /private на сервере: 0
```

Средняя задержка составляет не менее `0.15` секунды. Точное значение зависит от jitter, backoff и времени выполнения. По завершении HTTP-сессия и локальный сервер закрываются.

Тесты базовой загрузки явно отключают robots.txt и повторы и используют высокую частоту запросов. Настройки по умолчанию отдельно сохраняются в тесте конструктора.
