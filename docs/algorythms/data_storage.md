# Асинхронное сохранение данных

## Формат записи

После успешного `fetch_and_parse()` краулер формирует запись из полей `url`, `title`, `text`, `links`, `metadata`, `crawled_at`, `status_code` и `content_type`. Код статуса и тип содержимого берутся из последнего HTTP-ответа, в том числе после перенаправления. `crawled_at` создаётся в UTC и при записи преобразуется в строку ISO 8601. Дополнительные поля результата парсинга остаются в ответе `crawl()`, но в единый формат хранения не входят.

`prepare_record()` в `src/storage/base.py` проверяет наличие и типы полей. `DataStorage` задаёт асинхронные методы `save()` и `close()`, а также стандартные `save_many()` и `flush()`. Все хранилища сохраняют одну структуру данных и могут прочитать записи через `read_all()`.

## Файлы

`JSONStorage(path)` по умолчанию добавляет по одному JSON-объекту на строку. Формат JSON Lines позволяет дописывать большие наборы данных без чтения всего файла. `buffer_size` объединяет несколько записей в одну операцию записи; `flush()` и `close()` записывают остаток. Режим `json_lines=False` поддерживает форматированный JSON-массив с отступом `indent`. В этом режиме существующий массив перечитывается и обновляется через временный файл, поэтому для больших обходов следует выбирать JSON Lines.

`CSVStorage(path)` определяет заголовки из первой записи. Модуль `csv` экранирует кавычки, разделители и переводы строк. Списки ссылок и метаданные хранятся в ячейках как JSON, а `read_all()` восстанавливает их исходные типы. Параметр `encoding` задаёт кодировку; `buffer_size` управляет числом строк в одной записи. Оба файловых хранилища используют `aiofiles` и защищают общий буфер `asyncio.Lock`, поэтому конкурентные страницы не перемешивают строки.

## SQLite

`SQLiteStorage(path)` использует `aiosqlite`. `init_db()` создаёт таблицу `pages`, первичный ключ по URL и индексы по `crawled_at` и `status_code`. Поля `links` и `metadata` хранятся как JSON. Повторное сохранение URL обновляет его запись.

`save_many()` добавляет записи в буфер, а `batch_size` задаёт порог для пакетного `executemany()` и одного `commit()`. Значение по умолчанию — `1`: ошибка записи видна сразу. При большом потоке страниц можно увеличить `batch_size`; оставшийся пакет записывается при `flush()`, в конце `crawl()` или при `close()`. При ошибке SQL-транзакция откатывается, а данные остаются доступными для повтора.

## Интеграция с краулером

```python
from src.crawler.async_crawler import AsyncCrawler
from src.storage import SQLiteStorage

storage = SQLiteStorage("output/pages.db", batch_size=50)
crawler = AsyncCrawler(storage=storage)
try:
    await crawler.crawl(["https://example.com"], max_pages=10)
    print(crawler.get_storage_stats())
finally:
    await crawler.close()
```

Краулер сохраняет каждую успешно загруженную и разобранную страницу, включая прямой вызов `fetch_and_parse()`. Перед возвратом из `crawl()` он сбрасывает буфер. Ошибка записи повторяется `storage_retries` раз с паузами `storage_backoff × 2**n`; по умолчанию это два повтора с начальной паузой `0.05` секунды. Неудача сохраняется в `get_storage_stats()["failed_urls"]`, логируется и не удаляет страницу из результата обхода. Статистика показывает число принятых записей, ошибок и повторов; при неудачном сбросе буфера ожидающие URL помечаются как ошибки сохранения. `close()` закрывает HTTP-сессию и хранилище.

## Демонстрация и проверка

`python -m src.main` запускает локальный сайт с двумя страницами, обходит его отдельно с JSON Lines, CSV и SQLite, выводит число сохранённых и прочитанных страниц и показывает их заголовки. Файлы создаются в отдельном каталоге `output/storage_demo/<время запуска>/`, чтобы новые запуски не смешивали результаты.

Тесты `tests/storage/test_storage.py` и `tests/crawler/test_crawler_storage.py` проверяют формат записи, повторное открытие файлов и БД, экранирование CSV, пакетную вставку, индексы SQLite, конкурентную запись, автоматическое сохранение, повторы ошибок и чтение демонстрационных данных.
