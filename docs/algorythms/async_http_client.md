# Асинхронный HTTP-клиент

## Назначение

Асинхронный HTTP-клиент отвечает за загрузку веб-страниц без блокировки основного потока программы.

Клиент построен на основе:

- `asyncio` для управления асинхронными задачами;
- `aiohttp` для выполнения HTTP-запросов;
- `aiohttp.ClientSession` для повторного использования соединений;
- `aiohttp.TCPConnector` для connection pooling;
- `SemaphoreManager` для ограничения конкурентности.

Основной класс клиента находится в файле:

`src/crawler/async_crawler.py`

Управление семафорами находится в файле:

`src/concurrency/semaphore_manager.py`

## Создание клиента

Класс `AsyncCrawler` принимает следующие основные параметры:

```python
crawler = AsyncCrawler(
    max_concurrent=10,
    max_concurrent_per_domain=2,
    max_depth=2,
)
```

Параметры:

- `max_concurrent` — максимальное количество одновременно выполняющихся HTTP-запросов;
- `max_concurrent_per_domain` — максимальное количество одновременных запросов к одному домену;
- `max_depth` — максимальная глубина автоматического обхода ссылок.

Значения ограничений должны быть положительными целыми числами. Глубина обхода должна быть целым неотрицательным числом.

## HTTP-сессия

HTTP-сессия создаётся лениво при первом запросе.

Это означает, что создание объекта `AsyncCrawler` само по себе не открывает сетевые соединения.

При первом обращении к HTTP-клиенту создаётся `aiohttp.ClientSession`, использующая:

- общий пул соединений;
- ограничения количества соединений;
- таймаут подключения;
- таймаут чтения ответа.

Одна сессия повторно используется для всех запросов конкретного экземпляра `AsyncCrawler`.

Такой подход позволяет:

- не создавать новое соединение для каждого запроса;
- использовать connection pooling;
- уменьшить накладные расходы;
- корректно управлять сетевыми ресурсами.

Если существующая сессия была закрыта, при следующем запросе создаётся новая сессия.

## Таймауты

Для HTTP-запросов применяются отдельные ограничения времени:

- время установки соединения;
- время ожидания данных от сервера.

При превышении таймаута запрос завершается без падения всей программы.

В журнал записывается ошибка с указанием URL.

## Загрузка одной страницы

Метод:

```python
await crawler.fetch_url(url)
```

выполняет следующие действия:

1. Получает разрешение от `SemaphoreManager`.
2. Логирует начало загрузки.
3. Получает или создаёт HTTP-сессию.
4. Выполняет GET-запрос.
5. Проверяет HTTP-статус ответа.
6. Читает тело ответа как текст.
7. Логирует успешное завершение.
8. Освобождает глобальный и доменный семафоры.

Если запрос завершился ошибкой, метод фиксирует причину ошибки и возвращает пустую строку.

## Параллельная загрузка

Метод:

```python
await crawler.fetch_urls(urls)
```

создаёт отдельную асинхронную задачу для каждого URL.

Задачи запускаются конкурентно с помощью `asyncio.gather()`.

Количество одновременно выполняющихся запросов ограничивается семафорами, поэтому передача большого количества URL не приводит к неконтролируемому созданию сетевых подключений.

Результат содержит значение для каждого переданного URL.

Успешному запросу соответствует HTML-контент страницы. Неудачному запросу соответствует пустая строка.

## Управление конкурентностью

За ограничения конкурентности отвечает класс `SemaphoreManager`.

Он использует два уровня семафоров:

1. Глобальный семафор.
2. Отдельный семафор для каждого домена.

Глобальный семафор ограничивает общее количество одновременно выполняющихся запросов.

Доменный семафор ограничивает количество одновременных запросов к одному сайту.

Например, при настройках:

```python
SemaphoreManager(
    global_limit=10,
    domain_limit=2,
)
```

одновременно могут выполняться не более десяти запросов, но не более двух запросов к одному домену.

Перед началом запроса метод `fetch_url()` входит в асинхронный контекст менеджера:

```python
async with semaphore_manager.limit(url):
    ...
```

После завершения запроса или возникновения исключения оба семафора освобождаются автоматически.

Менеджер также отслеживает:

- текущее количество активных запросов;
- максимальное количество одновременно активных запросов;
- количество активных запросов для каждого домена.

## Обработка HTTP-ошибок

Перед чтением тела ответа вызывается проверка HTTP-статуса.

Ответы с кодами `4xx` и `5xx` приводят к `aiohttp.ClientResponseError`.

Причина ошибки сохраняется в формате:

```text
HTTP 404
```

или:

```text
HTTP 500
```

Ошибка одного запроса не останавливает обработку остальных URL.

## Обработка сетевых ошибок

Клиент обрабатывает:

- `aiohttp.ClientResponseError`;
- `aiohttp.ClientError`;
- `asyncio.TimeoutError`;
- ошибки некорректного URL.

Для сетевых ошибок сохраняются тип исключения и его текст.

Для таймаута сохраняется сообщение:

```text
Превышено время ожидания.
```

Все ошибки записываются в журнал с указанием URL.

## Хранение последней ошибки

При неудачной загрузке причина сохраняется внутри клиента.

Это позволяет очереди краулера получить конкретную причину отказа и записать её в `failed_urls`.

Перед новым запросом прежняя ошибка очищается, поэтому ошибка одного URL не используется для другого URL.

## Загрузка и парсинг

Метод:

```python
await crawler.fetch_and_parse(url)
```

объединяет HTTP-загрузку и HTML-парсинг.

Алгоритм работы:

1. Загружает HTML методом `fetch_url()`.
2. Проверяет, что был получен непустой результат.
3. Передаёт HTML в `HTMLParser`.
4. Возвращает структурированные данные страницы.

Результат содержит:

- исходный URL;
- заголовок страницы;
- основной текст;
- абсолютные ссылки;
- метаданные;
- изображения;
- заголовки `h1`, `h2`, `h3`;
- таблицы;
- списки.

Если загрузить страницу не удалось, возвращается результат с признаком ошибки и причиной отказа.

## Логирование

Клиент логирует:

- начало загрузки URL;
- успешную загрузку;
- начало парсинга;
- успешное завершение парсинга;
- HTTP-ошибки;
- сетевые ошибки;
- таймауты;
- предупреждения парсера.

Пример сообщения:

```text
Начало загрузки URL: https://example.com
```

Пример успешного завершения:

```text
Успешная загрузка URL: https://example.com
```

Пример HTTP-ошибки:

```text
HTTP-ошибка при загрузке URL https://example.com/missing: статус 404
```

## Закрытие клиента

После завершения работы необходимо вызвать:

```python
await crawler.close()
```

Метод закрывает `aiohttp.ClientSession` и освобождает сетевые ресурсы.

Повторное закрытие клиента безопасно.

Рекомендуемая схема использования:

```python
async def main() -> None:
    crawler = AsyncCrawler(max_concurrent=5)

    try:
        results = await crawler.fetch_urls(
            [
                "https://example.com",
                "https://www.python.org",
            ]
        )
        print(results)
    finally:
        await crawler.close()
```

## Последовательная и параллельная загрузка

При последовательной загрузке каждый следующий запрос начинается только после завершения предыдущего.

При параллельной загрузке несколько запросов ожидают ответы одновременно.

Для сетевых операций значительная часть времени расходуется на ожидание сервера. Асинхронный подход позволяет использовать это время для выполнения других запросов.

Демонстрационная программа измеряет оба варианта и выводит:

- время последовательной загрузки;
- время параллельной загрузки;
- отношение времени выполнения.

Фактическая разница зависит от скорости сети и времени ответа удалённых серверов.

## Тестирование

HTTP-клиент тестируется с помощью локального тестового HTTP-сервера.

Тесты проверяют:

- создание HTTP-сессии;
- повторное использование сессии;
- повторное создание закрытой сессии;
- корректное закрытие сессии;
- успешную загрузку страницы;
- обработку HTTP-ошибок;
- обработку таймаутов;
- обработку сетевых ошибок;
- параллельную загрузку;
- сохранение результатов неудачных запросов;
- глобальное ограничение конкурентности;
- ограничение запросов к одному домену;
- загрузку и парсинг HTML;
- преобразование относительных ссылок.

Использование локального сервера делает тесты независимыми от доступности внешних сайтов и скорости интернет-соединения.
