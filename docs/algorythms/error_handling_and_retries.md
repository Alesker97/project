# Обработка ошибок и автоматические повторы

## Компоненты

- `src/crawler/errors.py` — типы ошибок загрузки и парсинга.
- `src/crawler/retry_strategy.py` — выбор повторов, backoff, журнал попыток и статистика.
- `src/crawler/async_crawler.py` — HTTP-запросы, таймауты и применение стратегии.
- `src/main.py` — локальная демонстрация и сохранение отчёта.

## Классификация

| Тип | Причина | Повтор по умолчанию |
| --- | --- | --- |
| `TransientError` | HTTP `429`, `5xx`, таймаут | Да |
| `NetworkError` | Ошибка соединения, DNS или чтения ответа | Да |
| `PermanentError` | HTTP `4xx`, кроме `429`, некорректный URL | Нет |
| `ParseError` | Исключение при разборе HTML | Нет |

`asyncio.TimeoutError`, переданный непосредственно в `RetryStrategy`, преобразуется в `TransientError`. Ошибки соединения и чтения `aiohttp` преобразуются в `NetworkError`. Отмена задачи через `asyncio.CancelledError` передаётся вызывающему коду и не входит в статистику ошибок.

При загрузке `robots.txt` ответ `404` означает отсутствие файла правил и не считается ошибкой. Ответы `401`, `403`, `429` и `5xx` сохраняют правила запрета обхода. Проверка `robots.txt` выполняется перед каждой попыткой запроса страницы и после перенаправления.

## Алгоритм RetryStrategy

```python
strategy = RetryStrategy(
    max_retries=3,
    backoff_factor=2.0,
    retry_on=[TransientError, NetworkError],
    max_backoff=30.0,
)

result = await strategy.execute_with_retry(
    crawler.fetch_url,
    "https://example.com",
    raise_on_error=True,
)
```

`max_retries` — количество дополнительных попыток после первой. Стратегия последовательно вызывает переданную асинхронную функцию. После исключения она определяет его тип, записывает событие и проверяет лимит повторов. Если лимит не исчерпан, освобождённые запросом соединение и семафоры не удерживаются во время `asyncio.sleep()`. Следующая попытка снова проходит ограничитель скорости.

Пауза перед повтором после попытки с индексом `n`, начиная с нуля:

```text
min(backoff_factor × 2**n × множитель_типа, max_backoff)
```

По умолчанию множитель равен `1`. Для HTTP `429` он равен `2`. Словарь `backoff_by_type` позволяет дополнительно задать множитель для класса ошибки; `retries_by_type` ограничивает число повторов для класса. HTTP `500` без отдельной настройки получает максимум два повтора. `PermanentError` не повторяется даже при включении в `retry_on`.

`AsyncCrawler` использует эту же стратегию для страниц и `robots.txt`. Существующие параметры краулера сохраняются: `max_retries=2`, `backoff_factor=0.5`, `max_backoff=30.0`. В обычном режиме `fetch_url()` сам выполняет повторы и при конечной ошибке возвращает пустую строку, записав причину в `failed_urls`. Режим `raise_on_error=True` выполняет одну попытку и выбрасывает классифицированную ошибку для внешнего вызова `execute_with_retry()`; это исключает вложенные повторы.

## Таймауты

`connect_timeout`, `read_timeout` и `total_timeout` задают начальные значения для HTTP-запроса. По умолчанию используются `10`, `30` и `None` секунд соответственно. Для попытки с индексом `n` каждый заданный таймаут умножается на `1.5**n`. Настройки применяются к отдельному запросу через `aiohttp.ClientTimeout`; одна HTTP-сессия продолжает использоваться повторно. Таймаут не удерживает соединение или семафор до следующей попытки.

## Логирование, статистика и отчёт

Каждая ошибка записывает URL, номер попытки, тип, причину, паузу до следующей попытки и результат `retry` или `failed`. Успешное завершение также записывается с результатом `success`. `get_error_stats()` возвращает число ошибок по типам, число успешных операций после повтора, общее число повторов, среднюю фактически выдержанную паузу и отсортированный список URL с постоянными ошибками. `get_error_report()` добавляет к статистике `failed_urls` и журнал попыток. Новый вызов `crawl()` сбрасывает эти данные вместе с остальной статистикой обхода.

Локальная демонстрация в `python -m src.main` создаёт ответы `429`, `503`, `500`, `404`, `403` и медленную страницу, затем сохраняет `output/error_report.json`. Тесты в `tests/crawler/test_retry_strategy.py` и `tests/crawler/test_error_handling.py` проверяют классификацию, лимиты, паузы, увеличение таймаутов, статистику и отчёт.
